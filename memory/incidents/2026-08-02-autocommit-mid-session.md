# 2026-08-02 — drift-catcher закоммитил работу посреди активной сессии

**Kind:** unguarded-automation · **Severity:** medium · **Обнаружено:** ревью скила `/handoff`

## Что произошло

Во время сессии по переписыванию `skills/handoff/SKILL.md` (правки шли с 20:59
до 21:04) в 21:00:04 сработал launchd-джоб `com.georgij.agent-config-autocommit`
и забрал незавершённое состояние в коммит `5d0253c` с сообщением
«auto-drift: uncommitted changes caught 2026-08-02».

В коммит попали два несвязанных изменения: середина правки `SKILL.md` и строка
`memory/incidents/parking.jsonl`, записанная другим процессом.

## Чем это НЕ является

Не претензия к самому drift-catcher'у. `~/bin/agent-config-autocommit.sh` —
осознанный engineering control: правило «коммить правки правил сразу» —
administrative control, и оно уже проваливалось (97 некоммиченных изменений к
2026-07-07). Потеря причины в auto-drift коммите заложена **специально**: сам
такой коммит и есть сигнал тревоги, метрика H5 в `SYSTEM.md`, цель — 0 таких
коммитов в месяц. Это решение принято и не переоткрывается.

## Что действительно дефект

**1. Нет гейта «идёт сессия».** Скрипт срабатывает по календарю, а не по
состоянию. Агент, редактирующий файл в 21:00, гарантированно получает коммит
промежуточного состояния. Такой коммит хуже отсутствия коммита: в истории
появляется зелёная точка, за которой стоит наполовину переписанный файл, а
метрика H5 фиксирует нарушение дисциплины там, где дисциплина как раз
соблюдалась — правка была в процессе и её собирались коммитить с полным
сообщением через четыре минуты.

**2. `git add -A` в скрипте.** Строка:

```bash
git -C "$dir" add -A
```

Это ровно то, что запрещено собственным правилом владельца
`rules/parallel-agents.md`: «In a worktree NEVER `git add -A` / `git add .` —
explicit paths only». Запрет появился по инциденту 2026-06-13, где symlink
проскочил мимо dir-формы `.gitignore` и последующий merge удалил реальный venv
(`2026-06-04-parallel-agents-collisions.md`). `~/.claude` и `~/.codex` —
не worktree, но механика `.gitignore` там та же, а скрипт работает без
присмотра и с полным доверием к рабочему дереву.

## Возможные направления (не реализованы)

- Гейт по свежести: пропускать проход, если в репо есть файл с mtime моложе
  N минут — активная сессия, подождать до следующего запуска.
- Замена `add -A` на `add -u` + явный список untracked-путей, либо проверка
  `git status --porcelain` на symlink-записи перед add.
- Метрика H5 может отделять «auto-drift во время активной сессии» от
  «auto-drift по забытому диффу» — сейчас это одно и то же число, хотя первое
  говорит о таймере, а второе о дисциплине.

## Статус

Не исправлено: скрипт живёт вне `~/.claude`, его поведение — сознательное
проектное решение владельца. Инцидент зарегистрирован как вход для `/retro`.
