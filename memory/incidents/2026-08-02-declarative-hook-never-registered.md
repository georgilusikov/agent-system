# 2026-08-02 — `session-start-memory.sh` существует, но не подключён

**Kind:** dead-mechanism · **Severity:** medium · **Обнаружено:** ревью скила `/handoff`

## Что произошло

При регистрации нового SessionStart-хука для хэндофа выяснилось, что
`~/.claude/hooks/session-start-memory.sh` — полностью написанный, рабочий скрипт
(51 строка, обработка worktree-суффиксов, три уровня fallback для не-ASCII имён
проектов, вывод `additionalContext` через jq) — **нигде не зарегистрирован**.

Проверка:

```bash
grep -rn "session-start-memory" ~/.claude/settings.json ~/.claude/settings.local.json \
  <проект>/.claude/settings*.json <worktree>/.claude/settings*.json
# → ничего, exit 1
```

В `settings.json` событие `SessionStart` есть и содержит два других хука
(`herdr-agent-state.sh`, `bd prime`). То есть событие живое, а этот хук в нём
отсутствует.

## Почему это дорого

`CLAUDE.md` §Memory preflight предписывает: «Before any task that may have
history, FIRST step is checking memory». Скрипт был инженерным контролем этого
правила — он подавал `MEMORY.md` в контекст автоматически, не полагаясь на
дисциплину агента. Без регистрации правило снова держится **только на
декларации**, а именно провал декларативного memory preflight уже разбирался
как инцидент 2026-04-19 (`2026-04-19-skipped-memory-check.md`, severity high,
повторная работа по анализу Красинского).

Хук выглядит рабочим при любой проверке «есть ли у нас механизм»: файл на месте,
код корректный, `ls hooks/` его показывает. Не видно только того, что его никто
не зовёт.

## Класс ошибки

**Артефакт есть — потребителя нет.** Тот же класс, что в `CLAUDE.md`
§Meta-awareness: «Positive "feature wired/done" claim → verify the runtime
consumer reads your field». Здесь потребитель — не поле, а запись в
`settings.json`, но механика идентична: написанное не подключено, и зелёное
«файл существует» ничего не доказывает.

## Что делает это наблюдаемым

`gen_hook_registry.py` строит таблицу из `settings.json` — то есть показывает
только **зарегистрированные** хуки. Незарегистрированный файл в неё не попадает
вообще, поэтому реестр не отличает «хука нет» от «хук есть, но мёртв».

Кандидат в правило: реестр должен сканировать и `hooks/*.py|*.sh`, помечая
файлы, которых нет в `settings.json`, отдельным маркером «orphan».

## Статус

Не исправлено намеренно: регистрация чужого хука — решение владельца, не
побочный эффект ревью другого скила. Ожидает вердикта.
