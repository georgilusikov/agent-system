# Incident: пропущена проверка memory в начале сессии

## Симптом

Пользователь дал ссылку на NotebookLM с материалами Красинского + позже упомянул `~/Downloads/rules 3` — я провёл полный gap-анализ системы Красинского vs мои скиллы. После этого пользователь показал что у него уже есть:
- `~/Desktop/выступление красинского/analysis/` — 13 файлов анализа
- `~/.claude/projects/.../memory/MEMORY.md` → `krasinsky_session_2026-04-19.md` — memory об этой работе
- `/tmp/abtest/COMPARISON.md` — A/B тест /check
- 5 скиллов уже частично патчены (Output MUST + Input Checklist)
- Готовые YAML-шаблоны для `/falsify` и `/recover` в `11-implementation-plan.md`

**Я повторил ~80% работы которая уже была сделана.**

## Корневая причина (5 Whys)

1. **Почему повторил работу?** → Не знал что она уже была сделана.
2. **Почему не знал?** → Не прочитал `MEMORY.md` в начале сессии.
3. **Почему не прочитал?** → В моих rules нет правила «при триггере прошлой работы → первым шагом Read MEMORY.md».
4. **Почему правила нет?** → MEMORY.md упоминается в системном промпте как опция, но не как обязательный preflight для определённых триггеров.
5. **Почему не сделал preflight интуитивно?** → Default-bias: при появлении задачи «изучи систему X» → бросаюсь читать первоисточник X (NotebookLM), а не свою память о предыдущих сессиях.

## Корневая причина (процессная)

Отсутствует обязательный preflight «прочитай MEMORY.md» при триггерах прошлой работы. В системном промпте есть упоминание memory, но триггеры размыты («когда memories seem relevant»).

## Триггеры на которых должен был срабатывать preflight

- Имя проекта в memory упомянуто в задаче
- Пользователь дал ссылку на материалы (notebook, файл, папку) которые могут относиться к прошлой работе
- Пользователь сказал «у нас уже что-то делалось», «вспомни», «продолжи»
- Имя человека/системы которое могло быть в прошлых сессиях (Красинский, заказчик, проект)
- Запрос «изучи / разберись / собери рекомендации» по теме которая может иметь предысторию

## Design Injection

**Where:** `~/.claude/CLAUDE.md` (глобальные инструкции)

**Section:** «## Memory preflight (обязательный)»

**Text to inject:**
```markdown
## Memory preflight

Перед началом любой задачи которая может иметь предысторию (триггеры:
имя человека/проекта/системы упомянуто, ссылка на материалы, фразы
«вспомни / продолжи / разберись / собери / у нас уже»), ПЕРВЫМ шагом
запускай:

1. Read ~/.claude/projects/{currentProject}/memory/MEMORY.md (если есть)
2. Если в индексе есть релевантная запись — Read целиком
3. Только после этого приступай к задаче

Это сильнее общего совета «когда memories seem relevant». Триггеры —
явные, исключений нет. Цена pre-read = 1 Read tool call. Цена пропуска =
повтор полной работы.
```

**Why this prevents recurrence:** Делает preflight явным с конкретными триггерами вместо размытого «when relevant». Снижает default-bias на «бросаюсь читать первоисточник».
