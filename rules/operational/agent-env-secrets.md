# Agent briefs: секреты живут в .env репозитория

В каждом брифе агенту (Codex, grok, cloud worker), задача которого включает provider-адаптеры
(TTS, stock, Gemini, любой API): явная строка — «API-ключи ищи в `.env` корня репозитория;
загрузи его в окружение процесса ДО вызова адаптера. Отсутствие ключа в `os.environ` ≠
отсутствие ключа». Ключ отсутствует и в .env → STOP с перечнем проверенных мест, не «недоступен».

**Why:** 2026-07-11, nikita-video-engine — два STOP за один день по одной причине:
GOOGLE_API_KEY и PEXELS_API_KEY лежали в `.env`, но агент проверял только окружение процесса
и докладывал «ключ отсутствует». Потеряны два цикла owner-разблокировки.

**How to apply:** строка про .env — в шаблон брифа/goal-промпта рядом с prohibitions.
При STOP «нет ключа» первым делом `grep KEY_NAME .env` самому, прежде чем эскалировать owner'у.

Ошибка API limit/forbidden/unauthorized/quota → 3 диагностических запроса ДО вердикта
«не настроено»: (1) план/тир аккаунта, (2) текущий usage vs limit, (3) minimal-payload retry.
Сдача после первой ошибки = инцидент «first-failure surrender».
