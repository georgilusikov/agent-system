# Acceptance lock: принятое не переоткрывается

Владелец сказал «принято» → в отчёт/тикет/README пишется строка:

```
ACCEPTED: <артефакт или хеш> · <дата> · <кем принято>
REOPEN ONLY IF: новая жалоба владельца | изменился источник | упала регрессия
```

**После этой строки запрещено:** улучшать принятый артефакт по своей инициативе,
переигрывать выбранный baseline, «докручивать качество», предлагать альтернативную
архитектуру тому же результату. Не нашёл ни одного из трёх условий REOPEN — значит
вопрос закрыт, и это не повод для нового тикета.

**Почему.** Без явной отметки принятия каждый новый агент видит артефакт как
кандидата на улучшение и тратит цикл на то, что уже прошло приёмку. Симптом:
владелец второй раз слушает тот же звук / читает тот же отчёт. Отметка стоит одну
строку, а снимает целый класс повторной работы.

**Как применять:** перед тем как трогать что-либо готовое — `grep -r "ACCEPTED:"`
по отчётам домена. Нашёл → останавливаешься и спрашиваешь, какое из трёх условий
REOPEN сработало. Не нашёл → работаешь как обычно.

# Срок годности правила

Новое правило (в CLAUDE.md, AGENTS.md или rules/) добавляется только с двумя полями:

```
EXPIRES: <дата +90 дней>
EVIDENCE: <что подтвердит пользу — конкретное наблюдаемое срабатывание>
```

На ревизии (`/principles-review`): срок вышел, EVIDENCE не набралось → правило
**удаляется**, без обсуждения. Набралось → продлевается на 90 дней с указанием,
где именно сработало.

**Почему.** Правила накапливаются по инцидентам и не удаляются никогда: лимит строк
давит на объём, поэтому сжимаются формулировки, а число сущностей растёт. Модель
распределяет внимание по всем правилам сразу — каждое непроверенное ослабляет
проверенные. Срок годности — единственный механизм, который убирает правило по
качеству, а не случайно под давлением лимита.

EXPIRES: 2026-10-23
EVIDENCE: хотя бы один случай, где ACCEPTED-строка остановила повторную работу над
принятым артефактом, и хотя бы одно правило, удалённое по истечении срока.
