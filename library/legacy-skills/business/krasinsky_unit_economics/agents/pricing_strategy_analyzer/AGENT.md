# 💰 Pricing Strategy Analyzer

## Назначение
Анализирует и оптимизирует стратегии ценообразования для максимизации прибыли через сегментацию клиентов и понимание рыночных пробелов.

## Когда Использовать
- При разработке ценовой стратегии для нового продукта
- При оптимизации цен существующего продукта
- При анализе为什么不不同 сегменты клиентов готовы платить разную цену
- При принятии решений о корпоративных vs потребительских тарифах
- При планировании долгосрочных контрактов и подписок

## Входные Данные
- Описание продукта и его ценности для клиентов
- Информация о целевых сегментах (B2C, B2B, Enterprise)
- Текущие цены (если есть)
- Данные о стоимости приобретения клиента (CAC)
- Конкурентное окружение
- Горизонт планирования (для NPV расчетов)

## Алгоритм

### Шаг 1: Анализ Кривой Спроса
Поймите фундаментальный принцип ценообразования:

**Кривая спроса всегда убывает:**
- Чем выше цена → тем меньше клиентов купят
- Чем ниже цена → тем больше клиентов, но меньше прибыль с каждого
- **Цель:** Максимизировать ПРИБЫЛЬ, а не количество продаж

**Баланс ценообразования:**
- Слишком низкая цена → банкротство от нехватки прибыли
- Слишком высокая цена → банкротство от нехватки клиентов

### Шаг 2: Сегментация по Потребительскому Излишку
**Потребительский излишек (Consumer Surplus)** = разница между:
- Максимум, что клиент готов заплатить
- Тем, что он платит фактически

**Стратегия захвата излишка:**
- Разные сегменты готовы платить разную цену
- Чем крупнее клиент → тем выше готовность платить
- Создайте тарифы для каждого сегмента

**ОШИБКА:** Безлимитный подход (одна цена для всех)
- Лишает вас прибыли от крупных клиентов (IBM, Google, Meta)
- Оставляет деньги на столе

### Шаг 3: Анализ Рыночного Пробела ($1000 - $75000)
**Критический диапазон цен:** $1,000 - $75,000

**Проблема диапазона:**
- <$1000: Покупка по кредитке, быстро, без согласований
- >$1000: Попадает под корпоративные процедуры закупок
- >$75,000: Требует CEO согласования, тендеров, длинных циклов

**Подход Oracle (Enterprise pricing):**
- Очень дорогой софт ($75k+)
- Требует профессиональных продажников
- Длинный цикл сделки (6-18 месяцев)
- Высокая маржинальность оправдывает усилия

**Стратегия выбора цены:**
1. **До $1000:** Self-service, автоматические платежи, низкий CAC
2. **$1000 - $10000:** Обязательна телесная поддержка, mid-market
3. **$10000+:** Enterprise, персональный менеджер, долгий цикл сделки

### Шаг 4: Расчет NPV (Чистая Приведённая Стоимость)
**Учет временной стоимости денег:**

```
$100 сейчас > $100 через год
```

**Причины:**
- Инфляция (деньги теряют стоимость)
- Возможность инвестирования (можно заработать проценты)
- Риск (деньги сейчас гарантированы)

**Формула дисконтирования:**
```
NPV = Σ (Cash Flow / (1 + r)^t)
где:
r = ставка дисконтирования (обычно 10-20%)
t = период (год, месяц)
```

**Применение в ценообразовании:**
- Сравните одномоментную payment vs подписку
- Годовая подписка $100 сейчас vs $10/месяц
- Рассчитайте, что выгоднее с учетом NPV

### Шаг 5: Стратегия Ценовой Сегментации
**Варианты сегментации:**

1. **По размеру компании:**
   - Startup: $49/месяц
   - SMB: $299/месяц
   - Mid-market: $999/месяц
   - Enterprise: $5000+/месяц

2. **По функционалу:**
   - Free/Basic: Ограниченный функционал
   - Pro: Полный функционал
   - Enterprise: Custom + support

3. **По объему использования:**
   - По количеству пользователей
   - По количеству транзакций
   - По API calls

**Ключевой принцип:** Каждый сегмент платит по своей готовности

### Шаг 6: Анализ Конкурентов и Позиционирования
- Где ваши цены относительно конкурентов?
- Какой премиум за уникальный функционал?
- Есть ли возможности для price anchoring?

## Формулы

### Потребительский Излишек
```
Consumer Surplus = Willingness to Pay - Actual Price
```

### NPV (Чистая Приведённая Стоимость)
```
NPV = Σ (Cash Flow_t / (1 + r)^t)

где:
Cash Flow_t = денежный поток в период t
r = ставка дисконтирования (10-20% для бизнеса)
t = номер периода
```

### Максимизация Прибыли
```
Profit = (Price - Variable Cost) × Quantity Sold

Цель: Найти Price, который максимизирует Profit
```

### Сравнение Одноразовой Платежи vs Подписки
```
NPV(Subscription) = Σ (Monthly_Payment / (1 + r)^t)

Если NPV(Subscription) > One-Time_Payment:
→ Подписка выгоднее для вас
```

## Типичные Ошибки
1. **Одна цена для всех** — теряете прибыль от крупных клиентов
2. **Игнорирование рыночного пробела** — цена $2000 требует корпоративного согласования
3. **Не учет NPV** — сравниваете номинальные суммы без дисконтирования
4. **Максимизация выручки вместо прибыли** — больше продаж ≠ больше денег
5. **Отсутствие сегментации** — все клиенты разные по готовности платить

## Примеры из Статьи

### Пример 1: Безлимитный Подход (ОШИБКА)
**Ситуация:**
- Фиксированная цена для всех клиентов
- Включая гигантов типа IBM, Google, Meta

**Проблема:**
- IBM готова платить $100,000, а вы берете $100
- Малый бизнес готов платить $50, а вы берете $100 (отпугиваете)
- Теряете деньги на обоих концах

**Решение:**
- Сегментируйте клиентов
- Создайте тарифы для каждого сегмента
- Захватите потребительский излишек

### Пример 2: Oracle Strategy (Enterprise Pricing)
**Подход:**
- Очень дорогой софт: $75,000+
- Требует профессиональных продажников
- Длинный цикл сделки (6-18 месяцев)
- Высокая маржинальность оправдывает усилия

**Почему это работает:**
- Enterprise клиенты имеют бюджет
- Готовы платить за надежность и поддержку
- LTV одного клиента огромен

### Пример 3: Рыночный Пробел
**Диапазон $1000 - $75,000:**
- <$1000: Легко, быстро, без бюрократии
- >$1000: Корпоративные процедуры, тендеры, согласования
- >$75,000: Участие CEO, долгие переговоры

**Стратегия:**
- Либо оставайтесь под $1000 (self-service)
- Либо идите выше $75,000 (enterprise sales)
- Избегайте диапазона $1000-$10000 без команды продаж

## Ключевые Принципы
1. **"Кривая спроса всегда убывает"** — выше цена, меньше клиентов
2. **"Максимизируй прибыль, а не продажи"** — количество ≠ деньги
3. **"Сегментируй по готовности платить"** — разные клиенты = разные цены
4. **"Учитывай рыночный пробел"** — $1000 меняет всё
5. **"Деньги сейчас стоят больше"** — всегда дисконтируй будущие потоки
6. **"Захватывай потребительский излишек"** — не оставляй деньги на столе
