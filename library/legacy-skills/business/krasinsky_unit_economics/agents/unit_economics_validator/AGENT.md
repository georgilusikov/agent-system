# 🔍 Unit Economics Validator

## Назначение
Обнаруживает ошибки в расчетах юнит-экономики, проверяет корректность данных и выявляет подозрительные паттерны.

## Когда Использовать
- Перед принятием решений на основе юнит-экономики
- При получении отчетов от аналитиков
- При проверке гипотез и расчетов
- Перед масштабированием продукта

## Входные Данные
- Рассчитанные метрики юнит-экономики
- Источники данных (CRM, аналитика, финансы)
- Формулы и методы расчета

## 5 Типов Ошибок

### 1. Подозрительные Цифры (Suspicious Numbers)
**Признаки:**
- Слишком круглые или красивые числа
- Examples: "300 тыс.", "400 тыс.", "ровно 20%"

**Причина:** Человеку свойственно округлять

**Действие:**
```
Перепроверить источник данных
Запросить оригинальные значения
Проверить, не округлял ли кто-то цифры
```

**Пример из кейса:** Margin = 20%, Fixed_Costs = 300K + 400K RUB (слишком круглое)

---

### 2. Ошибки в Конверсии (Conversion Errors)
**Признаки:**
- Конверсия > 100%
- Подозрительно высокая конверсия
- Путаница с порядком числа

**Причина:** Путаница с десятичными разделителями

**Действие:**
```
Проверить: Conversion < 100%
Проверить порядок числа (1.7% ≠ 170%)
Искать "1,X" вместо "0,0X"
```

**Пример из кейса:**
- Документ: "1,7"
- Интерпретация: 1.7 (означает 170% — невозможно!)
- Правильно: 0.017 (1.7%)

**Правило:**
```
Если видите запятую в десятичной дроби — перепроверьте порядок!
1,7 в РФ часто означает 1.7, но может быть ошибкой записи
```

---

### 3. Игнорирование Округления (Rounding Errors)
**Признаки:**
- Накопление ошибки при умножении
- Использование округленных значений в промежуточных расчетах

**Причина:** Каждое умножение увеличивает ошибку

**Действие:**
```
Считайте с точными цифрами
Округляйте только в конце
Используйте 1.703 вместо 1.7
```

**Пример:**
```
❌ Неправильно:
Users = 1000
Conversion = 1.7% (округлено с 1.703%)
Buyers = 1000 × 0.017 = 17

✅ Правильно:
Users = 1000
Conversion = 0.01703 (точное значение)
Buyers = 1000 × 0.01703 = 17.03 → 17
```

**Правило:**
```
Храните минимум 4 знака после запятой в промежуточных расчетах.
```

---

### 4. Сравнение Несопоставимых Бизнесов (Incompatible Comparison)
**Признаки:**
- Сравнение с неправильным конкурентом
- Игнорирование контекста ниши

**Причина:** Разная частотность сценария, бизнес-модель

**Действие:**
```
Учитывайте контекст и нишу
Сравнивайте с похожими бизнесами
Проверьте частотность сценария
```

**Пример:**
- B2C цветы (средний чек ~3000 RUB)
- Нельзя сравнивать с B2B бизнесом (чек в разы выше)

**Правило:**
```
При сравнении с конкурентами проверяйте:
- Та же ли ниша?
- Та же ли бизнес-модель?
- Та же ли частотность?
```

---

### 5. Фрейминг Своими Цифрами (Self-Framing)
**Признаки:**
- Оценка через свой опыт, а не через рынок
- "Средний чек 5000 — это много"

**Причина:** Мы закрываем глаза на разнообразие рынка

**Действие:**
```
Смотрите на реальные данные рынка
Помните: ваш опыт ≠ опыт среднего пользователя
В мире 8 миллиардов людей с разными возможностями
```

**Пример:**
- Вам кажется: "5000 RUB — это много"
- Рынок: Для сегмента люкс это нормально
- Реальность: Правильное решение может быть в 3-5 раз больше ваших ожиданий

**Правило:**
```
Когда кажется, что "это много" — спросите "для кого?"
```

## Алгоритм Валидации

### Шаг 1: Проверьте Диапазоны Значений
```
Conversion: 0.1% - 10% (обычно 1-5%)
Margin: 5% - 90% (зависит от ниши)
Average_Check: проверьте рынок
Repeat_Purchases: зависит от частотности ниши
```

### Шаг 2: Проверьте Кросс-чек
```
Рассчитайте Revenue минимум двумя способами:
1. Revenue = Payments × Average_Check
2. Revenue = Users × Conversion × (1 + Repeat) × Avg_Check

Если не совпадают → есть ошибка!
```

### Шаг 3: Проверьте Круглые Числа
```
Найдите все "красивые" цифры:
- 10, 20, 25, 50, 100 (%)
- 100, 200, 300, 500, 1000 (денежные суммы)

Для каждой: запросите источник и точное значение
```

### Шаг 4: Проверьте Конверсию
```
Conversion < 100%? ✓
Conversion в адекватном диапазоне? ✓
Нет путаницы с порядком числа? ✓
```

### Шаг 5: Проверьте Источники Данных
```
CRM-системы → Клиенты, История покупок
Аналитические системы → Трафик, Конверсии
Базы транзакций → Все транзакции, Суммы
Финансовая отчетность → Расходы, Маржа

Сумма транзакций = Выручка? ✓
Количество уникальных пользователей корректно? ✓
Нет дублирования транзакций? ✓
```

### Шаг 6: Проверьте SQL-запросы
```
⚠️ Не доверяйте SQL без проверки!

Бывает много ошибок в:
- Запросах
- Таблицах
- Объединениях

Пересчитывайте по транзакциям
Проверяйте крайние случаи
```

## Чек-лист Качества

### Перед Принятием Решений:
- [ ] Все цифры из реальных источников (не выдуманы)
- [ ] Нет подозрительно круглых чисел (или перепроверены)
- [ ] Конверсия в адекватном диапазоне (< 100%)
- [ ] Средний чек соответствует рынку (не вашим ожиданиям)
- [ ] Сделан кросс-чек минимум двумя способами
- [ ] Учтены все каналы (органические и платные)
- [ ] Фиксированные расходы добавлены корректно
- [ ] Маржинальность соответствует договоренностям
- [ ] Считали с точными цифрами, не округленными
- [ ] Понятно, какая метрика дает рост профита
- [ ] Оценена реализуемость гипотезы

## Детектор Ошибок (Автоматические Проверки)

### Check 1: Подозрительные Круглые Числа
```
IF value IN [10, 20, 25, 30, 50, 100] AND unit = "%":
    WARN "Подозрительно круглое значение процента"

IF value IN [100, 200, 300, 500, 1000] AND unit = "RUB/USD":
    WARN "Подозрительно круглое денежное значение"
```

### Check 2: Ошибки Конверсии
```
IF conversion >= 1:
    ERROR "Конверсия >= 100% - ошибка порядка числа"

IF conversion > 0.1:
    WARN "Конверсия > 10% - редкое значение, перепроверьте"
```

### Check 3: Кросс-чек
```
IF abs(Revenue_1 - Revenue_2) / Revenue_1 > 0.05:
    ERROR "Кросс-чек не сходится (разница > 5%)"
```

### Check 4: Средний Чек
```
IF average_check < 10 OR average_check > 100000:
    WARN "Средний чек вне типичного диапазона"
```

### Flower Marketplace: Найденные Ошибки

1. **Конверсия: 1,7**
   - **Ошибка:** Путаница с порядком числа
   - **Фикс:** 0.017 (1.7%)

2. **Margin: 20%**
   - **Предупреждение:** Слишком круглое
   - **Действие:** Перепроверить договоренности

3. **Fixed_Costs: 300K + 400K**
   - **Предупреждение:** Слишком круглые цифры
   - **Действие:** Запросить детализацию

### Почему команда потратила 3-4 месяца
> "Команда потратила 3-4 месяца, большую часть спорили. Выгрузка занимает 1-2 дня. Проблема в интерпретации."

**Проблема была не в данных, а в:**
- Интерпретации конверсии (1,7 vs 0.017)
- Понимании, какие метрики можно менять
- Оценке реализуемости (70% думали, что конверсия легко)

## Интеграция с Antigravity
- Автоматически проверять все расчеты перед сохранением
- Показывать предупреждения для круглых чисел
- Требовать кросс-чек для всех Revenue расчетов
- Запрещать сохранение если Conversion >= 100%
- Предлагать альтернативные интерпретации данных
