# 💰 Hypothesis Cost Calculator

## Назначение
Рассчитывает стоимость тестирования гипотезы до проведения эксперимента, позволяя принимать взвешенные решения о приоритетности.

## Когда Использовать
- Перед запуском любого A/B теста
- При планировании сплит-тестов
- При оценке приоритетов гипотез в бэклоге
- Для сравнения эффективности разных каналов тестирования

## Входные Данные
- Описание гипотезы
- Размер выборки (требуемый для статистической значимости)
- Стоимость разработки (человеко-часы × ставка)
- Стоимость трафика (если платный)
- Временные затраты (календарные дни)
- Ожидаемый uplift (если применимо)

## Алгоритм

### Методика "Быстрой Оценки Гипотез" (из PHs18.3 & PHs18.5)

**Цель:** Оценить 50-100 гипотез за 2-3 часа (1-3 минуты на гипотезу)

#### Шаг 0: Подготовка Расчетной Таблицы

Рассчитайте опорные цифры юнит-экономики (через кросс-чек):
```
Users → Buyers → Payments → Revenue → Gross_Profit → Net_Profit
```

**Строка "для поиска точек роста":**
Скопируйте строчку с расчетом AMPU:
```
AMPU = Conversion × (1 + Repeat) × Average_Check × Margin
```

Эта строка позволяет быстро подставлять гипотетические значения метрик и видеть изменение профита.

#### Шаг 1: Не Спорьте! (Критическое правило)

**Почему НЕ надо спорить:**
- Споры — это трата времени
- Участники будут "продавать" свою правоту вместо получения знаний
- Цель — записать разные мнения и рассчитать, а не доказать кто прав

**Правило команды:**
- Один человек отвечает за тайминг
- Никто не спорит, все заполняют свою строчку
- Записывайте ВСЕ варианты мнений

#### Шаг 2: Запишите Гипотезу

Формат:
```
Название гипотезы
Метрика: [на какую метрику влияет]
Сложность: [1-5, где 1 = делается за день, 5 = очень сложно]
```

#### Шаг 3: Качественная Оценка (1-5 баллов)

**Шкала сложности:**
- **1** — Делается за день (минимальные изменения)
- **2** — Простое изменение (неделя работы)
- **3** — Средняя сложность (2-3 недели)
- **4** — Сложно (месяц+ работы)
- **5** — Очень сложно (крупные изменения, месяц+)

**Запишите:** Сложность: X

#### Шаг 4: Соберите Оценки Команды

**Правило:** Голос дает КАЖДЫЙ участник команды

**Метод IS-RICE (качественная оценка):**
- Каждый участник оценивает гипотезу от 1 до 5
- НЕ спорите между собой
- Запишите все ответы

**Пример:**
- Участник 1: 3
- Участник 2: 4
- Участник 3: 2
- Участник 4: 5

#### Шаг 5: Рассчитайте Среднее Арифметическое

```
Средняя_сложность = (3 + 4 + 2 + 5) / 4 = 3.5
```

**Почему среднее:**
- Сглаживает экстремальные оценки
- Отражает командное consensus
- Быстрый способ получения group estimate

#### Шаг 6: Оцените "Веру в Успех"

**Что такое "вера в успех":**
- Насколько вы верите, что гипотеза сработает?
- Экспертная оценка команды
- Не стесняйтесь, записывайте любые цифры

**Шкала:**
- **0.1** — Наверняка не сработает
- **0.25** — Маловероятно (25% шанс)
- **0.5** — 50/50
- **0.75** — Вероятно сработает (75% шанс)
- **0.9+** — Почти наверняка

**Правило:**
- Каждый участник называет свою цифру
- Возьмите среднее арифметическое

**Пример:**
- "Я верю на 20%" (0.2)
- "Не верю, что сработает" (0.1)
- "Возможно, 50/50" (0.5)

```
Средняя_вера = (0.2 + 0.1 + 0.5) / 3 = 0.27
```

#### Шаг 7: Подставьте в Юнит-Экономику

**Для каждой гипотезы:**

1. **Определите, какую метрику меняете**
   ```
   ❌ Неправильно: "Улучшим конверсию И средний чек"
   ✅ Правильно: "Улучшим конверсию на 0.5%"
   ```

2. **Оцените прирост метрики**
   ```
   Прирост_конверсии = Текущая × Вера_в_успех

   Пример:
   Текущая конверсия = 2%
   Вера в успех = 0.27
   Прирост = 2% × 0.27 = 0.54%
   Новая конверсия = 2% + 0.54% = 2.54%
   ```

3. **Подставьте в AMPU формулу**
   ```
   AMPU_новый = Новая_конверсия × (1 + Repeat) × Avg_Check × Margin
   AMPU_новый = 0.0254 × 1.2 × 3000 × 0.2 = 18.29 RUB
   ```

4. **Рассчитайте новый профит**
   ```
   Profit_новый = Users × (AMPU_новый - Cost_per_User) - Fixed_Costs
   ```

5. **Посчитайте разницу**
   ```
   Delta_Profit = Profit_новый - Profit_текущий
   ```

#### Шаг 8: Рассчитайте Доверительный Интервал

**Почему это важно:**
- Прирост 0.5% конверсии — это в пределах доверительного интервала
- CI может быть ±0.2%, значит реальный эффект 0.3%-0.7%
- Эффект может быть меньше, чем вы думали

**Формула CI для конверсии:**
```
CI = Mean ± (1.96 × √(p × (1-p) / n))

Пример:
Конверсия = 2% (0.02)
Users = 30,000
CI = ±0.22%

Реальный прирост 0.54% ± 0.22% = 0.32% - 0.76%
```

**Широкий CI → высокая неопределенность**

#### Шаг 9: Примите Решение

```
IF Delta_Profit > 0 AND Реалистично:
    → ДЕЛАТЬ (высокий приоритет)

IF Delta_Profit ≈ 0 OR Низкая вера:
    → ОТЛОЖИТЬ (низкий приоритет)

IF Delta_Profit < 0 OR Нереализуемо:
    → НЕ ДЕЛАТЬ
```

**Приоритизация:**
1. Сортируйте по Delta_Profit (по убыванию)
2. Сложность (1-5) — второй критерий
3. Возьмите топ 5-10 гипотез для работы

### 8-Шаговый Алгоритм Проверки Гипотез (ProductDo Methodology)

#### Шаг 1: Рассчитайте Опорные (Фактические) Цифры
Выгрузите реальные данные и постройте дерево метрик:
```
Users → Buyers → Payments → Revenue → Gross_Profit → Net_Profit
```

**Что получить:**
- Все 16 метрик юнит-экономики
- Текущие значения всех метрик
- Базовый профит

#### Шаг 2: Пересчитайте Без Округления
Считайте через конверсию для точных значений:
```
Избегайте округления в промежуточных расчетах
Используйте 1.703 вместо 1.7
Храните минимум 4 знака после запятой
```

#### Шаг 3: Выдвиньте Гипотезу
**Важное правило:** Выберите ОДНУ метрику для улучшения

```
❌ Неправильно: "Улучшим конверсию И средний чек И маржу"
✅ Правильно: "Улучшим конверсию с 2% до 3%"
```

Определите целевое значение метрики.

#### Шаг 4: Подставьте в Дерево Метрик
Измените ОДНУ цифру в дереве метрик:
```
Current: Conversion = 2%
Hypothesis: Conversion = 3%

Пересчитайте все зависимые метрики:
Buyers_new = Users × Conversion_new
Payments_new = Buyers_new × (1 + Repeat_Purchases)
Revenue_new = Payments_new × Average_Check
Gross_Profit_new = Revenue_new × Margin%
```

#### Шаг 5: Оцените Результат
Посмотрите на изменение финального профита:
```
Growth_Multiple = Gross_Profit_new / Gross_Profit_current
```

**Критерии оценки:**
- **Успех:** Кратный рост профита (2x, 3x, 10x)
- **Рассмотреть:** Умеренный рост (1.5x-3x)
- **Отклонить:** Незначительный рост (<1.5x)

#### Шаг 6: Проверьте Кросс-чек
Пересчитайте разными способами, убедитесь что сошлось:
```
Способ 1: Revenue = Payments × Avg_Check
Способ 2: Revenue = Users × Conv × (1+Repeat) × Avg_Check
Способ 3: Gross_Profit = Users × (ARPU - Cost_per_User)

Все способы должны дать одинаковый результат!
```

#### Шаг 7: Оцените Реализуемость
Задайте вопросы:
- Можно ли достичь этой метрики на практике?
- Сколько времени потребуется?
- Какие ресурсы нужны?
- Какие есть риски?

**Ранжирование по сложности:**
1. Margin — MEDIUM (недели)
2. Traffic — EASY (мгновенно, если есть бюджет)
3. Conversion — VERY_HARD (годы!)
4. Average_Check — HARD (долго)
5. Repeat_Purchases — ЗАВИСИТ от ниши

#### Шаг 8: Примите Решение
```
IF Кратный рост (2x+) AND Реализуемо:
    → ДЕЛАТЬ

IF Умеренный рост (1.5x-3x) OR Сложно оценить:
    → РАССМОТРЕТЬ

IF Незначительный рост (<1.5x) OR Нереализуемо:
    → НЕ ДЕЛАТЬ
```

### Альтернативный: Расчет Стоимости Теста

Если требуетcя A/B тестирование, рассчитайте стоимость:

#### Шаг A: Классификация Гипотезы
- **Product Hypothesis:** Изменения в продукте (UI/UX, фичи)
- **Marketing Hypothesis:** Каналы привлечения, креативы
- **Pricing Hypothesis:** Изменение цен, скидки
- **Technical Hypothesis:** Оптимизация производительности

#### Шаг B: Расчет Стоимости Разработки
```
Development Cost = (Hours × Hourly Rate) + Infrastructure Costs
```

#### Шаг C: Расчет Стоимости Трафика
```
Traffic Cost = Sample Size × Cost Per Visitor
```

#### Шаг D: Общая Стоимость Теста
```
Total Cost = Development Cost + Traffic Cost + Time Cost
```

#### Шаг E: ROI
```
Potential Value = (Current Revenue × Expected Uplift% × 12 months)
ROI = (Potential Value - Total Cost) / Total Cost
```

## Формулы

### Расчет выборки (для A/B теста)
```
n = (Zα + Zβ)² × (p₁(1-p₁) + p₂(1-p₂)) / (p₁ - p₂)²

где:
- Zα = 1.96 (для 95% доверия)
- Zβ = 0.84 (для 80% мощности)
- p₁ = baseline conversion rate
- p₂ = expected conversion rate
```

### Стоимость проверки
```
Test Cost = Dev Cost + (Sample Size × CPA) + Time Cost
```

### Эффективность
```
Efficiency Score = Potential Value / Test Cost
```

## Принципы из ProductDo

### "Одна метрика за раз" (CRITICAL!)
Не меняйте все одновременно. Иначе не поймете, что сработало.

**Почему это важно:**
- Эксперимент должен быть чистым
- Нужно выделить эффект конкретного изменения
- Иначе невозможно воспроизвести успех

**Правильный подход:**
```
Последовательный подход к гипотезам:
1. Изменяете конверсию → тестируете → измеряете
2. Только потом переходите к следующей метрике
3. В каждый момент времени работаете только с ОДНОЙ метрикой
```

### "Ищите кратный рост"
Оценивайте рост в разах, не в процентах.

- Если изменение метрики дает 1.1x роста — игнорируйте
- Ищите 2x, 3x, 10x потенциал
- Лучше одна метрика с 3x ростом, чем 5 метрик с 1.1x

### "Считай до трат"
Всегда рассчитывайте стоимость гипотезы ДО начала теста. Это предотвращает растрату бюджета на малозначимые эксперименты.

### "Дорогой путь — не всегда лучший"
Иногда быстрый и грязный тест дает 80% инсайтов за 20% стоимости идеального эксперимента.

### "Тренируйте нейронные связи"
Считайте вручную, чтобы понять зависимости. Скрипты бесполезны на этапе обучения.

**Почему автоматизация вредна на этапе обучения:**
- Вы не поймете зависимости между метриками
- Не сможете выдвигать гипотезы в голове
- Не будете предсказывать результаты "на лету"

**Цель:**
- Не цифры в Excel, а нейронная сеть в голове
- Через 3-6 месяцев команда запоминает все опорные цифры
- Мозг начнет предсказывать конверсии автоматически

### "Дерево метрик в голове"
Excel только отражение вашей модели мира. При выдвижении гипотезы вы должны знать, какую цифру менять.

**Что нужно уметь:**
- Воспроизвести все формулы из памяти
- При гипотезе знать цепочку изменений
- Пример: "Увеличим конверсию" → "понадобится изменить X, Y, Z"

### "Портфель гипотез"
Держите микс:
- **Quick Wins:** Низкая стоимость, высокий потенциал
- **Moonshots:** Высокая стоимость, высокий потенциал
- **Experiments:** Низкая стоимость, неопределенный потенциал

Избегайте:
- **Money Pits:** Высокая стоимость, низкий потенциал

## Анти-паттерны (из PHs18.3)

### "30-минутный скрипт" — Убийца Китов

**Ситуация (из практики):**
Менеджер пишет скрипт для оптимизации базы данных заявок (leads).

**Логика менеджера:**
- На совещании сказали: "Если с пользователем не связались в течение 30 минут, он нецелевой"
- Скрипт помечает все необработанные за 30 минут заявки как "нецелевые"
- Кажется логичным: "среднее время обработки 30 минут = все обрабатываем за 30 минут"

**Ошибка:**
- "Среднее 30 минут" ≠ "всех обрабатываем за 30 минут"
- Кто-то обрабатывается за 2 минуты, кто-то месяцами
- Скрипт помечает НЕцелевыми тех, кто НЕ дождался звонка

**Последствия:**
- "Нецелевые" с хорошим предиктом конвертируются в продажу
- Люди, которые очень хотят купить — сами перезвонят!
- Потеря самого ценного сегмента — "китов" (крупных клиентов)

**Реальный кейс (Фотостраница):**
- Скрипт запускался 30-го числа каждого месяца
- Каждый месяц убивал 10% доли платящих китов
- Люди с большим чеком (киты) терялись из-за скрипта

**Диагностика:**
1. Смотрите на метрику "количество обращений в поддержку" — выросло?
2. Смотрите на конверсию "нецелевых" — если конвертятся, значит ЦЕЛЕВЫЕ!
3. Проверьте, кто из "нецелевых" покупает — скорее всего, самые активные

**Почему это происходит:**
- Локальная оптимизация (db оптимизация)
- Система не скоординирована (лебедь рак и щука)
- Каждый элемент тащит в свою сторону
- Нет понимания всей цепочки ценности

**Решение:**
- НЕ помечайте как нецелевых на основе времени ожидания
- Используйте другие критерии квалификации лида

## Стратегии Оптимизации Воронки (Funnel Optimization)

**Источник:** PHs18. Испытание 3

### Три Стратегии Работы с Воронкой

У вас есть три подхода к оптимизации воронки продаж:

#### Стратегия 1: Оптимизация Начала Воронки (Top of Funnel)
- Первые шаги (посещение → регистрация → первый контакт)
- Много трафика, но мало доходит до конца
- Требует маркетингового бюджета

#### Стратегия 2: Оптимизация Конца Воронки (Bottom of Funnel)
- Последние шаги (оплата → подтверждение)
- Люди "доходят до конца", но не покупают
- Работает с существующим трафиком (б快速 ROI)
- **Лучший выбор когда:** Нет дизайнера, разработчик занят

#### Стратегия 3: Перепроектирование Всей Воронки
- Полный редизайн пути клиента
- Кардинально меняется бизнес-модель
- Очень дорого и долго

**Правило выбора:**
```
IF Нет дизайнера И Разработчик занят:
    → Оптимизируй КОНЕЦ воронки (наименьшие затраты)

IF Есть бюджет на трафик:
    → Оптимизируй НАЧАЛО воронки

IF Воронка сломана концептуально:
    → Перепроектируй всю воронку (но дорого!)
```

**Пример (из курса):**
- Воронка: 4841 человек дошли до последнего шага
- Команда оптимизировала конец воронки (малой кровью)
- Результат: рост конверсии на последних шагах

## Методика "Не Спорьте" (Team Alignment)

**Проблема:** Команды тратят время на споры вместо оценки гипотез

**Решение (из PHs18.3):**

1. **Один человек отвечает за тайминг**
   - Следит за временем
   - Останавливает споры
   - Говорит: "не спорьте, заполняйте строчки"

2. **Записывайте ВСЕ варианты мнений**
   - Если есть 2 разных мнения — скопируйте строчку
   - Посчитайте оба варианта
   - Сравните результаты

3. **Не "продавайте" свою правоту**
   - Спор = трата времени
   - Вы не получаете знания, когда спорите
   - Цель — разные оценки + расчет

4. **Среднее арифметическое — consensus**
   - Сложите все оценки
   - Разделите на количество участников
   - Получите групповую оценку

**Пример работы:**
```
Гипотеза: "Интеграция с банками"

Участник 1: "Сработает, вера 80%" (0.8)
Участник 2: "Не верю, 20%" (0.2)
Участник 3: "Возможно, 50%" (0.5)

Средняя вера = (0.8 + 0.2 + 0.5) / 3 = 0.5 (50%)

Прирост конверсии = 2% × 0.5 = 1%
```

**Почему это работает:**
- Быстро (1-2 минуты на гипотезу)
- Объективно (математика вместо эмоций)
- Включает всех участников
- Дает групповой consensus
