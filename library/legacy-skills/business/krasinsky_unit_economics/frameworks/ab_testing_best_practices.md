# A/B Testing Best Practices

**Источник:** ARTICLE_Habr_RetailRocket.txt
**Версия:** 1.0.0

## Суть
Формула идеального A/B теста и лучшие практики из опыта Retail Rocket. Ключевой фокус на метрической триаде (конверсия + средний чек + выручка), корректной сегментации данных и статистической достоверности.

## Пошаговый Алгоритм

### Формула идеального A/B теста
1. **Выдвигаем гипотезу** — четко формулируем, что хотим проверить
2. **Создаем альтернативу** — вариант Б с изменением
3. **Случайно делим трафик** — равномерное распределение на группы
4. **Одновременно замеряем** — конверсию и другие метрики
5. **Определяем достоверность** — статистическую значимость

### Требования для идеального теста
- ✅ Равномерное распределение аудитории по всем срезам
- ✅ Исключение сотрудников компании из теста
- ✅ Учет аннуляций и исполняемости заказов
- ✅ Использование специализированных сегментаторов

## Ключевые Метрики

### Метрическая триада (Три кита A/B тестирования)
При оценке результатов ВСЕГДА смотрите на три показателя:

1. **Конверсия** — основной показатель
2. **Средний чек** — критически важен для выручки
   - ⚠️ Рост конверсии при падении чека может СНИЗИТЬ прибыль!
3. **Выручка** — итоговый показатель эффективности

**Пример ошибки:** Конверсия выросла на 10%, но средний чек упал на 15% → прибыль упала

## Критические срезы данных

Результаты могут СИЛЬНО отличаться в зависимости от:
- 📱 **Устройство**: Desktop vs Mobile/Tablet
- 🌍 **География**: разные города
- 📊 **Источник трафика**: organic, paid, social, email

⚠️ **Всегда делайте сегментацию!** Иначе можно принять неправильное решение.

## Статистические методы для среднего чека

Для оценки среднего чека используйте один из двух методов:

1. **Байесовская статистика** — более современный подход
2. **Усечение выбросов** — отсекайте 3-5% самых крупных и мелких заказов

⚠️ **Почему это важно:** Экстремальные значения (один гигантский заказ) могут ИСКАЗИТЬ картину и показать ложный эффект.

## Типичные Ошибки

### Ошибка #1: Фокус только на конверсии (Метрическая слепота)
- Смотрите только на конверсию
- Игнорируете средний чек и выручку
- Рост конверсии может маскировать падение прибыли

**Пример:**
- Конверсия: +10% ✅
- Средний чек: -15% ❌
- Итого: ПРИБЫЛЬ упала!

### Ошибка #2: Игнорирование сегментации (Агрегированная ловушка)
- Смотрите только на агрегированные данные
- Desktop и Mobile показывают РАЗНЫЕ результаты
- Эффект в одном сегменте маскируется другим

**Пример из практики:**
- Desktop: Конверсия выросла на 15% ✅
- Mobile: Конверсия упала на 10% ❌
- Aggregated: Без изменений ⚠️

### Ошибка #3: Не учтены выбросы в среднем чеке
- Один гигантский заказ искажает средний чек
- Показывает ложный эффект
- Стандартные статистические тесты не работают

**Пример:**
- Обычно: средний чек $50
- Один заказ: $10,000
- Итог: средний чек $75 (искажен!)

### Ошибка #4: Сотрудники в выборке
- Сотрудники компании тестируют изменения
- Их поведение отличается от обычных пользователей
- Искажают результаты теста

### Ошибка #5: Не учтены аннуляции
- Считаете все заказы, включая отмененные
- Не учитываете исполняемость заказов
- Конверсия растет, но реальных денег нет

## Чек-лист идеального A/B теста
- [ ] Выдвинута четкая гипотеза
- [ ] Создан альтернативный вариант
- [ ] Трафик распределен случайно и равномерно
- [ ] Замеры производятся одновременно
- [ ] Определена статистическая достоверность
- [ ] Проверена метрическая триада (Конверсия + Средний чек + Выручка)
- [ ] Исключены сотрудники компании
- [ ] Учтены выбросы в среднем чеке
- [ ] Проверена сегментация по устройствам, географии, источникам
- [ ] Учтены аннуляции и исполняемость заказов
