# Leverage Hunting — поиск горлышек, рычагов и слепых зон

Работает РАНЬШЕ дебаг-протоколов: когда проблема не сформулирована («растём медленно»,
«буксует», «что мы не видим»). `dev/why_analysis` копает одну ошибку, `dev/triage`
выбирает между гипотезами известной проблемы — этот скилл строит карту, где искать.

## Когда НЕ применять

- Конкретная ошибка / traceback → `dev/why_analysis`
- ≥3 конкурирующих гипотезы одной проблемы → `dev/triage`
- Разрешение конфликта требований → `business/toc_cloud`
- Нужна диаграмма петель → `triz/causal_loop_diagram` (совместим: карта отсюда — вход туда)

## Что ищем / stop-criteria

1. **Bottleneck** — узел, ограничивающий поток: перед ним очередь, после — простой (TOC).
2. **Leverage point** — узел, где вмешательство непропорционально дёшево (лестница Meadows).
3. **Blind spot** — узел, которого нет на карте пользователя: неизмеряемое, необсуждаемое.

Stop когда: ≥1 bottleneck с [O]-evidence или дешёвым probe; ИЛИ ≥3 рычага на разных
ярусах + ≥2 blind spots; ИЛИ честный вердикт «потолок системы» (поток равномерный,
независимые улучшения дают одинаково малый прирост → ограничение снаружи границы).

## Протокол

### §1. Система, цель, единица потока
3 строки: границы системы; цель; единица потока (заявка, видео, PR, клиент, рубль).

### §2. Карта потока
Этапы прохождения единицы от входа до выхода. Для каждого — [O]-признаки, не мнения:
очередь ДО этапа (backlog, WIP, pending), wait vs processing time, утилизация.
Каждому признаку тег [O]/[I]/[S]/[A].

### §3. Bottleneck scan (TOC)
Constraint = максимальная очередь ДО + простой ПОСЛЕ. Классы: физический (мощность),
процессный (ручной гейт), policy (правило/привычка — чинится дешевле всех), знание.
Улучшение узла НЕ на constraint даёт нулевой прирост потока.

### §4. Leverage scan (Meadows, 6 ярусов)

| Ярус | Что менять |
|---|---|
| 1. Параметры | числа, лимиты, бюджеты |
| 2. Feedback loops | усилить/ослабить петлю, убрать задержку |
| 3. Информационные потоки | кто ЧТО видит и когда |
| 4. Правила | инцентивы, гейты, права |
| 5. Цель системы | ради чего оптимизируем |
| 6. Парадигма | из чего цель выросла |

Чем выше ярус — тем сильнее рычаг. Находки только на ярусе 1 = слабый результат,
ищи минимум до яруса 3.

### §5. Blind-spot scan (обязательные 4 прохода)
1. **Negative space:** чего НЕТ на карте §2 — не измеряется, не логируется?
2. **Assumptions audit:** что принято как данность? Каждое допущение → [A] + цена проверки.
3. **Pre-mortem:** «год прошёл, система умерла» — 3 некролога с разными механизмами;
   причина вне карты §2 = blind spot.
4. **Неуслышанные:** кто сталкивается с системой, но не участвует в обсуждении?

### §6. Мульти-ролевой режим (опционально)
Для больших систем — параллельные исполнители с непересекающимися ролями:
Constraint Hunter (очереди/утилизация), Systems Cartographer (петли/ярусы 2-6),
Pre-mortem Prophet (некрологи), Naive Outsider (наивные вопросы к допущениям),
Data Skeptic (что не измеряется, proxy-метрики, «конфиг говорит X — артефакт Y»).
Правила синтеза: исполнители завышают severity ~30% — каждый Critical перепроверь
сам по файлам/данным; raw output ≠ finding; дубли склей.

### §7. Leverage Map (output)

| ID | Узел | Тип | Evidence | Ярус | Probe | Цена probe |
|---|---|---|---|---|---|---|
| L1 | ... | bottleneck / leverage / blind-spot | [O]/[I]/[S]/[A] + факт | 1-6 | дешёвая проверка | 5 мин / час / день |

После таблицы: **Blind spots** блоком (≥2 или «не нашёл + где искал»); **Verdict**
(горлышко найдено / потолок системы / нужны данные); **Next** — топ-3 probe.
Скилл выдаёт карту и probe. Фиксы — отдельная задача после подтверждения probe.

## Известные грабли

- Оптимизация не-горлышка: узел не на constraint → поток не вырос
- Потолок системы принят за горлышко: 3+ независимых подхода дают одинаковый прирост ≤ε
  → это потолок данных/рынка, ищи ограничение снаружи
- Симптом ≠ constraint: жалобы видны ПОСЛЕ горлышка, очередь копится ДО
- Мульти-ролевой синтез без верификации: Critical исполнителя транслирован как факт

## FORBIDDEN

- Объявлять bottleneck по одному [A]-допущению без probe
- Чинить найденное в этом же прогоне — только карта и probe
- Карта только с ярусом 1 («добавь ресурсов») — это не анализ
- Выдуманные метрики/логи/статусы (см. `_agent_shared/standards/` no-fabricated-evidence
  или аналог в runtime)
- Пропуск blind-spot scan §5

## Hard fail

- Нет Leverage Map таблицы → эссе, не анализ
- Все узлы [A] и ни одного probe → карта мнений
- Нет blind-spot блока → главная цель скилла не выполнена
