# Phase 1: Decomposition

## Цель
Разбить исходное утверждение (Claim) на 3-12 атомарных sub-claims, каждый из которых можно проверить независимо.

## Алгоритм

### Шаг 1: Декомпозиция
Разложить исходный claim на минимальные проверяемые утверждения.

**Правила декомпозиции:**
- Каждый sub-claim содержит ОДНО проверяемое утверждение
- Убрать неконкретные формулировки ("многие считают", "все знают")
- Убрать эмоциональные окраски
- Сохранить суть

### Шаг 2: Классификация типов

Каждый sub-claim получает тип:

| Тип | Описание | Проверяем? |
|-----|---------|------------|
| `[EMPIRICAL]` | Проверяется наблюдениями, экспериментами, данными | ✅ Да — через web search, научные статьи |
| `[LOGICAL]` | Проверяется логическим рассуждением | ✅ Да — через формальную логику |
| `[NORMATIVE]` | Ценностное суждение ("должно быть так") | ⚠️ Частично — можно анализировать основания |
| `[DEFINITIONAL]` | Зависит от определения понятия | ⚠️ Частично — через герменевтику и дефляционизм |

### Шаг 3: Определить критерий проверяемости

Для каждого sub-claim зафиксировать:
- **Что именно проверяем** (какой факт/связь)
- **Какой тип evidence нужен** (данные/логика/экспертиза)
- **Проверяем** или **помечаем как непроверяемый** с объяснением

### Шаг 4: Отфильтровать

- Если sub-claim дублирует другой → объединить
- Если sub-claim фундаментально непроверяем → пометить `[NOT_VERIFIABLE]` с причиной
- Оптимальное количество: 3-7 для quick, 5-12 для deep

## Output

```
Sub-claims:
  - SC1: "[текст]" [EMPIRICAL] — проверяем через: [метод]
  - SC2: "[текст]" [LOGICAL] — проверяем через: [метод]
  - SC3: "[текст]" [NORMATIVE] — ограниченная проверка: [метод]
  ...
```
