## 🔥 ТОП-7 механик (встречаются чаще всего)

### Механика #1: Выход на предыдущую работу

**Описание:** Вместо того чтобы продавать текущее решение, помоги клиенту выполнить работу, которая идёт ПЕРЕД покупкой.

**Почему работает:**
- Предыдущая работа — узкое место (клиент застревает)
- Снимает барьер перед покупкой
- Часто предыдущая работа имеет больший TAM

**Кейсы где применялось:**
- Кейс "Выход на предыдущую работу обеспечил PMF" → рост выручки +75%
- Кейс "AJTBD на креативном рынке" → рост продаж на 15%

**Как применить:**
1. Построй граф работ (промпт #4)
2. Найди работу, которая идёт ПЕРЕД покупкой
3. Создай бесплатное/дешёвое решение для предыдущей работы
4. Активируй в текущую работу (платный продукт)

**Пример:**
```
Текущая работа: Купить недвижимость (платный продукт)
    ↑
Предыдущая работа: Понять какая недвижимость мне подходит (бесплатно!)
    ↑
Предыдущая работа: Узнать о вариантах на рынке (контент!)
```

**Результат:** Клиент получает ценность ДО покупки → доверие → конверсия ↑

---

### Механика #2: Фокусировка на одном сегменте

**Описание:** Вместо того чтобы продавать "всем", выбери ОДИН сегмент и говори только на его языке.

**Почему работает:**
- Разные сегменты имеют РАЗНЫЕ работы
- Универсальное сообщение не работает ни для кого
- Фокус на одном → 10x ясность ценности

**Кейсы где применялось:**
- Кейс "Сегментация и фокус дали доп. выручку" → рост conversion rate
- Кейс "Средний чек вырос в 3 раза за счёт сегментации" → +3x средний чек
- Кейс "FinTech: конверсия выросла на 39%" → +39% CR

**Как применить:**
1. Сгенерируй 5-10 сегментов (промпт #2/3)
2. Выбери ТОП-1 по привлекательности (TAM × ценность × прибыльность)
3. Создай отдельный лендинг для этого сегмента
4. Говори на языке ЭТОГО сегмента (работы, эмоции, контекст)

**Результат:** Конверсия ↑30-75% (вместо "для всех" → "для меня!")

---

### Механика #3: Tripwire (дешёвое первое предложение)

**Описание:** Вместо того чтобы продавать дорогой продукт сразу, предложи дешёвое/бесплатное решение для малой работы.

**Почему работает:**
- Снижает барьер входа (страх, бюджет)
- Клиент "пробует" продукт без риска
- После покупки tripwire → легче продать основной продукт

**Кейсы где применялось:**
- Кейс "Tripwire удвоил платящих клиентов" → +2x платящих

**Как применить:**
1. Построй граф работ (промпт #4)
2. Найди Micro Job или Small Job (быстрая, дешёвая работа)
3. Создай tripwire-предложение ($7-50) для этой работы
4. После tripwire → активируй в основной продукт

**Пример:**
```
Основной продукт: Курс по недвижимости ($500)
    ↑
Tripwire: Чек-лист проверки квартиры ($7)
    ↑
Lead magnet: 10 ошибок при покупке (бесплатно)
```

**Результат:** +100% платящих клиентов (барьер снижен)

---

### Механика #4: Смена бизнес-модели через работы

**Описание:** Если текущая бизнес-модель не работает, измени её на основе работ клиента.

**Почему работает:**
- Текущая модель может не соответствовать работам
- Работы показывают как клиент ХОЧЕТ платить

**Кейсы где применялось:**
- Кейс "Смена бизнес-модели" → улучшение метрик

**Как применить:**
1. Построй граф работ (промпт #4)
2. Пойми КОГДА и КАК клиент готов платить
3. Измени модель:
   - Subscription → One-time payment?
   - Freemium → Paid trial?
   - Pay-per-use → Flat fee?
4. Тестируй через A/B

**Пример:**
```
Было: Subscription ($50/месяц)
Проблема: Клиент использует 1 раз в 3 месяца → отменяет

Стало: Pay-per-use ($20 за использование)
Результат: Клиент платит когда нужно → retention ↑
```

---

### Механика #5: Детализация графа работ → поиск узких мест

**Описание:** Детально распиши ВСЕ работы клиента → найди где застревает → оптимизируй.

**Почему работает:**
- Клиент застревает на конкретных шагах
- Оптимизация узких мест даёт наибольший эффект

**Кейсы где применялось:**
- Кейс "IT-продукт дал доп. выручку" → рост доходности
- Кейс "Продажи на клиента выросли на 15%" → +15% sales per customer

**Как применить:**
1. Используй промпт #4 (Граф работ)
2. Оцени силу проблемы на каждом шаге (0-10)
3. Найди топ-5 разрывов (сила ≥8/10)
4. Создай гипотезы для каждого разрыва
5. Тестируй через A/B

**Результат:** Конверсия/ретеншн ↑20-50% (узкие места устранены)

---

### Механика #6: ROI-фокус для B2B

**Описание:** Для B2B продай не "удобство", а конкретный ROI (сколько клиент заработает/сэкономит).

**Почему работает:**
- B2B покупают на основе ROI, а не эмоций
- Конкретные цифры → легче обосновать перед боссом/бухгалтерией

**Кейсы где применялось:**
- Кейс "ROMI и стратегия роста" → улучшение метрик

**Как применить:**
1. Построй граф работ B2B-клиента (промпт #3)
2. Для каждой работы посчитай ROI:
   - Сколько времени экономит?
   - Сколько денег экономит/зарабатывает?
   - Какой риск снижает?
3. Покажи ROI в цифрах на лендинге
4. Дай калькулятор ROI (интерактив!)

**Пример:**
```
Было: "Удобная CRM-система"
Стало: "Экономит 15 часов в неделю на рутине = $3000/месяц"

Результат: CR ↑40% (ROI очевиден)
```

---

### Механика #7: OODA-цикл стратегии

**Описание:** Быстрая итерация: Observe → Orient → Decide → Act → снова Observe.

**Почему работает:**
- Рынок меняется → нужна гибкость
- Быстрые эксперименты > долгое планирование

**Кейсы где применялось:**
- Кейс "OODA-цикл стратегии" → адаптация к изменениям

**Как применить:**
1. **Observe:** Собери данные (интервью, метрики, промпт #4)
2. **Orient:** Проанализируй (где разрывы? что не работает?)
3. **Decide:** Прими решение (какую гипотезу тестировать?)
4. **Act:** Запусти эксперимент (1-2 недели)
5. **Observe:** Смотри результаты → снова Observe

**Результат:** Адаптация к рынку в 5-10x быстрее чем конкуренты

## 📋 Чек-лист: Как применить механики к своему продукту

### Шаг 1: Диагностика (1-2 часа)

- [ ] Построй граф работ (промпт #4)
- [ ] Оцени силу проблемы на каждом шаге (0-10)
- [ ] Найди топ-5 разрывов (сила ≥8/10)
- [ ] Определи текущую метрику (CR? LTV? Revenue?)

### Шаг 2: Выбор механики (30 мин)

**Если CR низкий (<2%):**
- → Механика #2 (Фокус на сегменте)
- → Механика #3 (Tripwire)
- → Механика #1 (Выход на предыдущую работу)

**Если LTV низкий:**
- → Механика #5 (Детализация графа → поиск узких мест в продукте)
- → Механика #4 (Смена бизнес-модели)

**Если средний чек низкий:**
- → Механика #2 (Фокус на сегменте с большим бюджетом)
- → Механика #6 (ROI-фокус для B2B)

**Если не знаешь что делать:**
- → Механика #7 (OODA-цикл → быстрые эксперименты)

### Шаг 3: Применение (1-4 недели)

- [ ] Сформулируй гипотезу (формат из experiment-framework.md)
- [ ] Создай MVP (лендинг, прототип, A/B-тест)
- [ ] Запусти эксперимент (1-2 недели)
- [ ] Измерь результат (CR, LTV, Revenue)
- [ ] Если работает → масштабируй
- [ ] Если не работает → выбери другую механику

### Шаг 4: Масштабирование (1-3 месяца)

- [ ] Примени 2-3 механики параллельно
- [ ] Создай backlog экспериментов (experiments-backlog.md)
- [ ] Запускай 1-2 эксперимента в неделю
- [ ] Масштабируй выигрышные механики

## 🔗 Паттерны успеха (общее для всех кейсов)

### Паттерн #1: Начинай с интервью
**Все кейсы:** Перед изменениями проводили Switch-интервью (5-10 штук)

**Почему:** Промпты дают гипотезы, интервью — факты

**Как:** [jtbd-interview-guide.md](../../[standards.md]/4.%20jtbd-research/jtbd-interview-guide.md)

---

### Паттерн #2: Фокус на одном разрыве
**Все кейсы:** Не пытались исправить всё сразу, фокусировались на 1-2 критичных разрывах

**Почему:** Ресурсы ограничены, фокус даёт результат

**Как:** Выбирай разрывы с силой ≥8/10

---

### Паттерн #3: Быстрые эксперименты
**Все кейсы:** Не делали полный редизайн, запускали A/B-тесты (1-2 недели)

**Почему:** Быстрая валидация, низкий риск

**Как:** [experiment-framework.md](../../[standards.md]/2.%20experiments-framework/experiment-framework.md)

---

### Паттерн #4: Измеряли метрики
**Все кейсы:** До/после измеряли ключевые метрики (CR, LTV, Revenue)

**Почему:** Без метрик не поймёшь что работает

**Как:** [metrics-glossary.md](../../[standards.md]/3.%20metrics-analysis/metrics-glossary.md)

---

### Паттерн #5: Итерировали
**Все кейсы:** Не останавливались на одном эксперименте, итерировали 3-5 раз

**Почему:** Первая гипотеза редко идеальна

**Как:** OODA-цикл (Observe → Orient → Decide → Act)

---

## 💡 Антипаттерны (чего НЕ делать)

### ❌ Антипаттерн #1: Полный редизайн без валидации
**Проблема:** Потратишь 3-6 месяцев на редизайн, который может не сработать

**Решение:** Тестируй изменения через A/B-тесты (1-2 недели)

---

### ❌ Антипаттерн #2: Работаешь со всеми сегментами сразу
**Проблема:** Универсальное сообщение не работает ни для кого

**Решение:** Выбери ОДИН сегмент, создай отдельный лендинг

---

### ❌ Антипаттерн #3: Не проводишь интервью
**Проблема:** Гипотезы ≠ факты, высокий риск ошибки

**Решение:** 5-10 Switch-интервью обязательны!

---

### ❌ Антипаттерн #4: Не измеряешь метрики
**Проблема:** Не понимаешь что работает, что нет

**Решение:** До/после измеряй CR, LTV, Revenue, CAC

---

### ❌ Антипаттерн #5: Останавливаешься после одного эксперимента
**Проблема:** Первая гипотеза редко идеальна

**Решение:** Итерируй 3-5 раз, пока не найдёшь работающее решение

## 🎯 Практический пример применения механик

### Кейс: SaaS-продукт, CR лендинга 1.2%

**Шаг 1: Диагностика**
- Построили граф работ (промпт #4)
- Нашли разрыв: "Не понимают какой план выбрать" (сила 9/10)
- Текущий лендинг: универсальный для всех

**Шаг 2: Выбор механики**
- Механика #2 (Фокус на сегменте)
- Механика #3 (Tripwire)

**Шаг 3: Применение**
1. Сгенерировали 5 сегментов (промпт #2)
2. Выбрали топ-1: "Агентства с командой 5-10 человек"
3. Создали отдельный лендинг для этого сегмента
4. Добавили tripwire: "Бесплатный аудит за 15 минут" (помогает выбрать план)
5. Запустили A/B-тест (2 недели)

**Результат:**
- CR: 1.2% → 3.1% (+158%!)
- Tripwire конвертит в платный: 45%
- Итоговый рост платящих: +90%

**Время:** 3 недели (вместо 3 месяцев редизайна)
**Экономия:** $8000 (редизайн стоил бы $10000)
