# Example: Загадочная деградация сервера

## Input
"У нас веб-сервис, время ответа выросло с 50мс до 3 секунд. Мы уже проверили: CPU 30%, RAM 40%, база отвечает за 10мс. Всё в норме, но сервис тормозит. Проблема появляется только в рабочие часы (9-18), хотя трафик в это время не выше ночного."

## Execution Trace

### Фаза 0: Фиксация проблемы
- **Система:** Веб-сервис (API)
- **Ожидание:** Время ответа ~50мс
- **Факт:** Время ответа ~3000мс (рост в 60 раз)
- **Контекст:** Только в рабочие часы 9-18, ресурсы сервера свободны

### Фаза 1: Поиск парадоксов

**Факты:**
1. Latency выросла в 60 раз
2. CPU 30% (не перегружен)
3. RAM 40% (не перегружена)
4. База данных отвечает за 10мс (быстро)
5. Проблема только 9-18 (рабочие часы)
6. Трафик 9-18 не выше ночного

**ПАРАДОКС #1:**
- Ожидание: Если latency выросла в 60 раз, хотя бы один ресурс (CPU/RAM/DB) должен быть на пределе
- Факт: Все ресурсы свободны
- Почему странно: Задержка не берётся из ниоткуда — что-то держит запрос 3 секунды

**ПАРАДОКС #2:**
- Ожидание: Если трафик одинаковый днём и ночью, проблема должна быть и ночью
- Факт: Ночью всё работает нормально
- Почему странно: При одинаковой нагрузке результат разный — значит есть скрытый фактор, связанный со временем суток

### Фаза 2: Генерация гипотез

**ГИПОТЕЗА #1: Внешний сервис, вызываемый в процессе обработки**
- Объясняет парадоксы: #1, #2
- Механизм: Сервис вызывает внешний API (SSO, геолокация, антифрод), который тормозит в рабочие часы. CPU/RAM/DB сервера свободны, потому что он просто ЖДЁТ ответа от внешнего сервиса.
- Скрытый фактор: Внешний API не мониторится, его latency не входит в дашборд

**ГИПОТЕЗА #2: Cron-задача, запускающаяся в рабочие часы**
- Объясняет парадоксы: #2 (время), но НЕ объясняет #1 (ресурсы свободны)
- Отброшена: если cron грузит систему, CPU/RAM должны расти

### Фаза 3: Тестирование

**ТЕСТ ДЛЯ ГИПОТЕЗЫ #1:**
- Действие: Добавить трейсинг всех внешних HTTP-вызовов (OpenTelemetry / простой лог с таймингом)
- Если верна: Один из внешних вызовов покажет latency ~2.9с в рабочие часы
- Если неверна: Все внешние вызовы быстрые, задержка внутри сервиса

### Фаза 4: Корневая причина

- **Элемент:** Вызов к внешнему SSO-сервису для валидации токенов
- **Механизм:** SSO-сервис перегружен в рабочие часы (все сотрудники логинятся), отвечает за 2.8с вместо 5мс
- **Маскировка:** SSO-вызов не мониторился; CPU/RAM/DB — классические метрики, но они не показывают время ожидания внешних сервисов

## Output Summary
- **Корневая причина:** Внешний SSO-сервис деградирует в рабочие часы
- **Парадоксы объяснены:** Ресурсы сервера свободны (он ждёт, а не работает); проблема только днём (SSO нагружен пользователями)
- **Next step:** Кэширование токенов или переход на локальную валидацию JWT
