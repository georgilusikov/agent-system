# TRIZ Domain Profile: Engineering (Классическая инженерия)

## Mapping: Реальный мир → TRIZ

### Substances (S)
| Физический объект | TRIZ-роль |
|---|---|
| Деталь, заготовка, изделие | **S1 (Изделие)** |
| Инструмент, станок, приспособление | **S2 (Инструмент)** |
| Смазка, охлаждающая жидкость, среда | **S3 (Добавка)** |

### Fields (F) — полный MATHEM
| Категория | Примеры |
|---|---|
| **M**echanical | Давление, удар, трение, вибрация, центробежная сила |
| **A**coustic | Ультразвук, инфразвук, резонанс, кавитация |
| **T**hermal | Нагрев, охлаждение, фазовый переход, излучение |
| **cH**emical | Окисление, катализ, pH, полимеризация |
| **E**lectric | Ток, электростатика, электролиз, пьезоэффект |
| **M**agnetic | Постоянное поле, электромагнит, ферромагнетик, вихревые токи |

## Типичные противоречия (ТП)
1. **Прочность ↔ Вес** — классическая для аэрокосмоса, транспорта
2. **Точность ↔ Производительность** — обработка, сборка
3. **Надёжность ↔ Стоимость** — массовое производство
4. **Температура ↔ Структура** — термообработка, сварка
5. **Мощность ↔ Энергопотребление** — двигатели, насосы

## Приоритетные навыки
1. `@vepoli` — Su-Field модели наиболее естественны для физических систем
2. `@standards` — 76 стандартов были созданы для инженерных задач
3. `@effects` — физические эффекты MATHEM напрямую применимы
4. `@contradictions` + `@forty_principles` — матрица Альтшуллера для инженерных параметров
5. `@resource_analysis` — ОЗ и ОВ легко определяются в физическом пространстве

## Ресурсы типичные
- **Вещественные**: материал детали, смазка, отходы обработки, среда (воздух, вода)
- **Энергетические**: тепло процесса, вибрация, гравитация, магнитное поле Земли
- **Информационные**: цвет, форма, звук работающего механизма
- **Временные**: паузы между операциями, ночь, сезон
- **Пространственные**: пустоты, каналы, поверхности

## Anti-Patterns (Типичные ошибки)
- ❌ Сразу искать приёмы без анализа ресурсов
- ❌ Игнорировать надсистему (среду, соседние детали)
- ❌ Забывать про ФЕПОЛЬ (стандарт 2.4.1) — самый мощный класс решений
- ❌ Не делать RCA при повторяющихся дефектах
