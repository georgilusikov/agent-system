# TRIZ Domain Profile: Business (Бизнес / Организация)

## Mapping: Бизнес → TRIZ

### Substances (S)
| Бизнес-объект | TRIZ-роль |
|---|---|
| Клиент, заказ, продукт, контракт | **S1 (Изделие)** |
| Сотрудник, отдел, процесс, инструмент | **S2 (Инструмент)** |
| Платформа, CRM, ERP, агент | **S3 (Посредник)** |
| Рынок, регулятор, конкурент | **Надсистема** |

### Fields (F) — бизнес-аналоги
| MATHEM | Бизнес-аналог |
|---|---|
| Mechanical | Денежный поток, бюджет (давление/сила) |
| Acoustic | Коммуникация, обратная связь, NPS (сигналы) |
| Thermal | Мотивация, вовлечённость, "выгорание" (тепловая аналогия) |
| Chemical | Трансформация: обучение, рост компетенций, реорганизация |
| Electric | Управляющие решения, приказы, KPI (потоки управления) |
| Magnetic | Культура, бренд, миссия (притяжение без прямого давления) |

## Типичные противоречия (ТП)
1. **Качество ↔ Стоимость** — premium vs mass-market
2. **Скорость ↔ Качество** — time-to-market vs quality
3. **Контроль ↔ Автономия** — микроменеджмент vs делегирование
4. **Масштаб ↔ Персонализация** — конвейер vs индивидуальный подход
5. **Инновации ↔ Стабильность** — disruption vs core business

## Приоритетные навыки
1. `@contradictions` — бизнес-trade-offs: формулировка ТП → поиск разделения
2. `@trimming` — удаление бюрократии, лишних звеньев, паразитных процессов
3. `@functional_analysis` — карта функций организации: кто что делает, какие паразитные функции
4. `@s_curve` — определение фазы развития продукта/рынка для стратегических решений
5. `@ikr` — "Клиент САМ покупает без продавца", "Отчёт САМ формируется"

## Ресурсы типичные
- **Вещественные (People/Assets)**: сотрудники, партнёры, офис, оборудование, инвентарь
- **Энергетические (Capital)**: бюджет, инвестиции, кредит, гранты
- **Информационные**: клиентская база, аналитика, know-how, патенты, отзывы
- **Временные**: сезонность, время клиента, нерабочее время, сроки контрактов
- **Пространственные**: каналы продаж, география, онлайн-присутствие

## Anti-Patterns (Типичные ошибки)
- ❌ Решать проблемы наймом (вместо анализа — "нам нужно больше людей")
- ❌ Игнорировать S-кривую продукта (инвестировать в зрелый продукт)
- ❌ Не видеть паразитные функции ("этот отчёт нужен" — а кто его читает?)
- ❌ Формулировать проблему как "нет денег" (ТП: нужны ресурсы ↔ бюджет = 0 → ищи бесплатные ресурсы)
- ❌ Забывать про ИКР: "Проблема решена, а затраты = 0"

**💡 Ошибки прогнозирования и анализа из практики:** Перед выдачей рекомендаций просматривайте анти-паттерны (мыслительные и аналитические ошибки мастеров ТРИЗ) через скрипт `python _agent_shared/scripts/metodolog_lookup.py --db anti_patterns --query "ошибка или метод"`. Копируйте оттуда методы предотвращения провалов.

## Линии эволюции бизнес-моделей

Используйте эти линии для прогнозирования следующего шага бизнес-системы через `@zrts` или Boris Phase 1/Phase 4.

### 1. Монетизация
Единичная продажа → Подписка (SaaS) → Freemium → Usage-based (pay-per-use) → Marketplace (комиссия) → Platform-as-Infrastructure (API economy)

### 2. Канал продаж
Прямые продажи (salesforce) → Партнёрская сеть → Self-service (онлайн) → Product-Led Growth (продукт продаёт сам) → Community-Led Growth → Ecosystem-Led Growth

### 3. Масштабирование
Ручной труд → Стандартизация процессов → Автоматизация → AI-augmented operations → AI-автономные операции → Zero-Operations (система обслуживает сама себя)

### 4. Создание ценности
Продукт (вещь) → Продукт + сервис → Сервис без продукта (XaaS) → Outcome-as-a-Service (платишь за результат) → ИКР: ценность создаётся без усилий клиента

### 5. Данные
Нет данных → Сбор данных (analytics) → Персонализация на данных → Data-as-Product (монетизация данных) → Data Network Effects (чем больше пользователей — тем лучше продукт)

### 6. Конкурентное преимущество (Moat)
Нет moat → Бренд → Эффект масштаба → Switching costs → Сетевые эффекты → Регуляторный moat (лицензии/патенты) → Экосистемный lock-in

### 7. Модель управления (Контроль)
Ручной контроль (микроменеджмент) → Жёсткие правила/KPI → Адаптивное управление (обратная связь) → Предиктивное (на основе данных/ИИ) → Самоорганизующаяся команда/ДАО (ИКР)

**Использование:** Определите текущую позицию бизнеса на каждой линии. Прогнозируйте следующий шаг. Если система "застряла" — ищите противоречие, блокирующее переход.

## Платформы и сетевые эффекты

> **Когда применять:** Если анализируемая система — платформа, маркетплейс, экосистема или двусторонний рынок.

### Типы сетевых эффектов

| Тип | Описание | Пример |
|---|---|---|
| **Прямой** | Больше пользователей → больше ценность для каждого | Telegram, WhatsApp |
| **Косвенный (кросс-сторонний)** | Больше продавцов → больше покупателей → больше продавцов | Uber, Airbnb |
| **Data network effect** | Больше данных → лучше AI → лучше продукт | Waze, Google Search |
| **Контентный** | Больше создателей → больше контента → больше потребителей | YouTube, TikTok |
| **Локальный** | Сетевой эффект работает только в рамках региона/ниши | Delivery, такси |

### Чек-лист анализа платформы

- **Проблема "курица и яйцо":** Какую сторону привлекать первой? Какая сторона более ценна? Какой минимальный масштаб для запуска?
- **Мультихоминг:** Могут ли пользователи быть на нескольких платформах одновременно? (если да — moat слабый)
- **Switching costs:** Что удерживает пользователей? (данные, репутация, социальный граф, привычка, интеграции)
- **Winner-takes-all или Winner-takes-most?** Есть ли место для 2-3 игроков или рынок схлопывается в монополию?
- **Регуляторный риск:** Может ли регулятор "разбить" платформу? (антимонопольное, GDPR, местные законы)
- **Дезинтермедиация:** Могут ли стороны начать работать напрямую, обходя платформу?

### ИКР для платформ
Идеальная платформа: **стороны САМИ приходят, САМИ создают ценность друг для друга, САМИ решают конфликты, а платформа лишь обеспечивает доверие и ликвидность.**
