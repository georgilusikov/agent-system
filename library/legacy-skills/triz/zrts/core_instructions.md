## Phase 0: S-Curve Anchor (Обязательно!)

**ПЕРЕД выбором закона** определите стадию S-кривой:

| Стадия | Признаки | Стратегия |
|--------|----------|-----------|
| **1 (Рождение)** | Мало патентов, низкая эффективность, высокий потенциал | Поиск правильного принципа действия |
| **2 (Рост)** | Рост патентов/рынка, быстрое улучшение параметров | Poly-сборка, расширение функций |
| **3 (Зрелость)** | Параметры на плато, оптимизация деталей, много патентов | Micro-переход, свёртывание, замена поля |
| **4 (Угасание)** | Параметры упёрлись в предел, рост только через удорожание | Переход на новый принцип (другая S-кривая) |

**Правило:** Закон ZRTS даёт разные рекомендации на разных стадиях. Без S-Curve anchor — СТОП.

**Дискриминатор стадии (отвечай на вопросы строго по порядку, первый «да» = стадия; номер сработавшего вопроса запиши в отчёт):**
1. Ключевой параметр упёрся в физический предел, улучшение возможно только через непропорциональное удорожание? → **Stage 4**
2. Ключевой параметр на плато (рост заметно замедлился), конкуренция идёт на уровне деталей/оптимизации/цены? → **Stage 3**
3. Ключевые параметры быстро растут, рынок/патенты расширяются? → **Stage 2**
4. Ни один «да» (принцип действия ещё не доказан, эффективность низкая, потенциал высокий)? → **Stage 1**

> ⚠️ **Guard clause:** Если ни на один вопрос дискриминатора нельзя ответить на основании фактов (нет данных о динамике ключевого параметра) — **СТОП**. Не выбирай закон и не строй векторы. Сначала запроси/найди данные о динамике параметра: стадия «на глаз» делает все 8 рекомендаций недостоверными.

## 🏭 Протокол выполнения / Execution Protocol (8 Законов)

### 1. Переход в надсистему (Mono → Bi → Poly)
**CHECK S-CURVE FIRST!**
- **Stage 1-2 (Growth):** → Poly-system (1+1=2). Комбинируйте!
- **Stage 3-4 (Maturity):** → STOP Poly! Go Micro-level. Упрощайте!

**Poly Types:**
- Однородные (1+1): Усиление мощности
- Сдвинутые (1+1'): Расширение диапазона
- Инверсные (1+Anti-1): Разрешение противоречий

### 2. Переход Macro → Micro
Заменяем механику на структуру вещества.
**MATHEM Chain:** Мех → Аку → Тепло → Хим → Электро → Магнит → ЭМ

### 3. Динамизация (Flexibility + Adaptivity)
**A. Ритмика:** Согласование частот (резонанс/антифаза)
**B. Динамизация:** Жёсткое → Шарниры → Гибкое → Жидкость → Поле
**C. Адаптивность:** Само-регулирование (Smart Response)

### 4. Закон Анти-Системы
Система + Враг co-эволюционируют.
- **Зеркальная эволюция:** Броня ↔ Снаряд
- **Захват:** Использовать энергию врага против него (Айкидо)

### 5. Неравномерность развития частей
Части системы развиваются с разной скоростью → узкое звено тормозит всё.
- **Действие:** Найти «отстающую» подсистему (bottleneck)
- **Стратегия:** Подтянуть отстающую ИЛИ перепроектировать систему под новый принцип
- *Пример:* Двигатель мощнее, трансмиссия не выдерживает → усилить трансмиссию ИЛИ перейти на прямой привод

### 6. Вытеснение человека
Ручное → Механизированное → Автоматизированное → Автономное (без оператора).
- **Действие:** Определить, где человек — «узкое звено» (скорость, точность, усталость)
- **Стратегия:** Заменить функцию человека в этом узле
- *Пример:* Ручная сварка → Роботизированная → Лазерная автономная

### 7. Свёртывание (Trimming)
Ideal Machine = функция БЕЗ машины. Компоненты исчезают, функция переносится.
- **Действие:** Какой компонент можно убрать, если его функцию выполнит соседний/среда/надсистема?
- **Связь:** Подробный протокол свёртывания → `@trimming`
- *Пример:* Убрать ручку из ведра → ведро с формой для захвата

### 8. Рост управляемости и адаптивности
Жёсткое → Регулируемое → Адаптивное → Самоорганизующееся.
- **Действие:** Определить текущий уровень управляемости системы
- **Стратегия:** Шаг к следующему уровню
- *Пример:* Фиксированный термостат → Программируемый → AI-термостат (учится)

## 🏆 Выбор вектора-лидера (счётное ранжирование, ОБЯЗАТЕЛЬНО)

Для каждого из ≥3 векторов посчитай два числа и запиши их в отчёт:
- `L` = сколько из 8 законов поддерживают этот вектор (целое число, перечисли номера законов)
- `R` = доступность ресурсов для перехода: **3** = всё уже есть в системе/ОЗ; **2** = нужны доступные внешние ресурсы; **1** = нужны дефицитные/дорогие ресурсы

**Score = L × R.** Лидер = вектор с максимальным Score. Укажи числа `L`, `R`, `Score` для каждого вектора.

Tie-break при равном Score (применяй правила по порядку, номер сработавшего правила запиши в отчёт):
1. Меньший срок теста (из Transition Contract).
2. Лучшее согласование со стадией S-кривой.
3. Меньшая стоимость отката при опровержении.

> ⚠️ **Guard clause:** Лидер объявлен без чисел `L`/`R`/`Score` у ВСЕХ векторов — **СТОП**, отчёт невалиден. «Этот вектор кажется самым естественным» — не критерий.

## ❌ Антипаттерны / Anti-Patterns
- ❌ **Wrong Stage Prescription:** Poly для Stage 3 (уже поздно!) — на зрелой стадии нужен Micro-переход
- ❌ **Ignoring Anti-System:** Забыть про конкурента/анти-систему
- ❌ **Jumping to Field:** Сразу на магнитное поле без прохождения MATHEM-цепочки
- ❌ **S-Curve Blindness:** Применять законы без определения стадии
- ❌ **Single Law Tunnel:** Проверить один закон и остановиться — проверяй все 8

**Пример плохого вывода (❌) vs исправленного (✅):**

❌ «Vector 1 — лидер, потому что динамизация выглядит самым естественным шагом для этой системы.»

✅ «Vector 1: L=3 (законы #3, #8, #2), R=3 → Score=9. Vector 2: L=2 (#1, #5), R=2 → Score=4.
Vector 3: L=2 (#2, #7), R=1 → Score=2. Лидер — Vector 1 (Score 9 > 4 > 2), tie-break не понадобился.
Стадия определена вопросом #2 дискриминатора (параметр на плато) → Stage 3, Micro-стратегия согласована.»
