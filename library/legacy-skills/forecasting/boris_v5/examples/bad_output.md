# Bad Output (Boris v5)

## Input
Оценить идею: облачный CI для ML-моделей, сократить время релиза.

## ❌ Что сделано ПЛОХО

### Phase 0: Нет фундамента
> "Объект анализа — облачный CI для ML, KPI — скорость."

**Проблемы:**
- Нет PoA-цепочки (Input → Mechanism → Output → Effect → KPI Event).
- Нет Boundary (что внутри / что снаружи?).
- KPI "скорость" — не метрика, нет порога ("скорость чего? Относительно чего?").
- Stakeholders отсутствуют (кто платит? кто блокирует?).
- Intent/режим не выбран.

### Phase 1: Бедная карта
> "Надсистемы: DevOps-экосистема, Рынок ML-инструментов."
> "Подсистемы: Пайплайн, Модели."

**Проблемы:**
- 2 надсистемы (надо ≥6): пропущены регулятор, клиенты/пользователи, облачные провайдеры, конкуренты, сообщества DevOps.
- 2 подсистемы (надо ≥5): пропущены инфраструктура, данные, мониторинг, артефакты.
- Нет ресурсного анализа.
- Нет вредных функций.
- Нет предела/порога текущего PoA и "другой кривой".

### Phase 2: Фантазийный прогноз
> "Этот продукт вырастет в 3 раза за 2 года."

**Проблемы:**
- Нет S-curve стадии и нет доказательств (нет ≥3 индикаторов из рубрики).
- Нет Base/Bull/Bear сценариев.
- Прогноз "в 3 раза" — голословный, нет `[DATA]`/`[OBS]`/`[REF]`.
- Нет антисистем/угроз.
- Нет Risk Register.

### Phase 3: Пропущена ценность
> (секция отсутствует)

**Проблемы:**
- Нет JTBD, Four Forces, WTP, Friction.
- Непонятно, за что платить и кто готов.

### Phase 4: Слабые решения
> "Вариант 1: Добавить больше GPU. Вариант 2: Использовать Spot-инстансы. Вариант 3: Оптимизировать docker-образы."

**Проблемы:**
- 3 кандидата, все из одной ветки (инфраструктура) — нет PoA-diversity.
- Нет TC/PC (какое противоречие решаем?).
- Нет кандидата по "Протоколу Литвина" (radical trimming).
- Нет zero-system check.
- Нет Morphological Matrix.
- Нет Solution-Scenario Matrix.

### Phase 5: Нет аудита
> "Рекомендуем Вариант 2. Спасибо!"

**Проблемы:**
- Нет Risk Register.
- Нет Experiments / Assumption Ledger.
- Нет Core-PIZDEJ.
- Нет ICE Scoring.
- Нет Confidence / Raw Score / Verdict.
- Нет Next Actions.

---

## 📊 Итог: почему это "плохой" отчёт

| Критерий | Результат |
|---|---|
| Ясность задачи | ❌ Нет PoA, нет KPI-порога |
| Глубина карты | ❌ 2+2 вместо 6+5 |
| Доказательность | ❌ Нет Evidence tags |
| Разнообразие решений | ❌ Все 3 из одной ветки |
| Аудит и самокритика | ❌ Полностью пропущен |
| **Confidence** | **Не рассчитан** |
| **Verdict** | **Не сформирован** |

Такой отчёт создаёт иллюзию анализа, но на самом деле не даёт пользователю ни прогноза, ни инструментов принятия решения.
