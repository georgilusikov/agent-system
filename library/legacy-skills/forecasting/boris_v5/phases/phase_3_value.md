# 💰 Phase 3: VALUE ARBITRAGE

> **Цель:** понять, какую ценность создаёт решение для пользователей и платящих клиентов, выявить силы, влияющие на принятие решения, оценить готовность платить (WTP) и трение (Friction). Определить сегменты non‑consumption и потребность в pivot.

---

## 📌 Артефакты Phase 3

### 3.1 Job To Be Done (JTBD)

Сформулируйте главную работу, которую пользователь пытается выполнить (глагол + объект + контекст). Разделите на функциональный, эмоциональный и социальный слой. Используйте интервью, наблюдения или secondary data; пометьте источник Evidence.

### 3.2 Four Forces

Используйте модель 4 сил (Push, Pull, Anxiety, Habit) для оценки энергетики переключения. Дайте числовую оценку каждой силе (1–10) и краткое описание, приведите источник:

| Force | Score (1‑10) | Description | Evidence |
|---|---|---|---|
| Push | | | |
| Pull | | | |
| Anxiety | | | |
| Habit | | | |

Рассчитайте Switching Energy = Push + Pull, Resistance = Anxiety + Habit. Определите, вероятно ли переключение (Switch likely / Unlikely / Marginal).

### 3.3 WTP Proof

Оцените готовность платить. Используйте минимум две из трёх прокси‑метрик:

| Proxy | Metric | Value | Evidence |
|---|---|---|---|
| Loss | Потеря/ущерб без решения (штрафы, упущенные сделки, увольнение) | | |
| Spend | Сколько уже тратят на аналоги (коучи, курсы, софтовые инструменты) | | |
| Time | Сколько времени уходит на работу без решения (часы, стоимость труда) | | |

Если проект немонетарный (например, внутренняя реформа), замените Spend на «Effort spend» (ресурсы, политический капитал).

### 3.3.1 Plausibility check (порядки величин) — чтобы не верить WTP “на слово”
Если WTP/экономика выглядят слишком хорошо или слишком плохо, сделайте 1 быструю проверку порядками величин:
- **Сопоставление с Loss/Spend:** может ли ценность/экономия реально быть такого порядка?
- **Единицы времени/денег:** сколько человеко‑часов/денег должно “освободиться”, чтобы это окупалось?
- **Ограничитель принятия:** даже если ROI огромный, есть ли лимит по внедрению/доверию/регуляторике?

Выход: “OK/сомнительно/невозможно” + что нужно проверить данными (интервью, пилот, лог).

### 3.4 Friction Index

Проанализируйте трение на разных стадиях (Discovery, Evaluation, Purchase/Adoption, Onboarding, Use). Для каждого укажите тип трения (cognitive/time/effort), оценку (1–10), и ботлнек:

| Stage | Stakeholder | Friction Type | Score (1‑10) | Bottleneck |
|---|---|---|---|---|

Определите «Critical Stage» с наибольшим трением и предложите возможные решения (например, Knowledge Wizard для перевода технических инсайтов в понятный язык).

### 3.5 Non‑Consumption Analysis

Определите сегменты, которые не используют решения и почему. Используйте категории Overshot/Undershot/No Access/No Skill/No Awareness. Для каждого сегмента оцените размер и возможность его привлечь.

### 3.6 Value Summary

Подведите итог: насколько велика работа, какие силы доминируют, готовы ли платить, где основной friction и какие сегменты пока недоступны. Это поможет принять решение о необходимости Pivot или о фокусе на определённом сегменте (например, enterprise vs consumer).

### ✅ Gate Check

- [ ] JTBD сформулирован (глагол + объект + контекст).
- [ ] Four Forces оценены численно.
- [ ] WTP содержит ≥ 2 прокси.
- [ ] Friction Index заполнен минимум для 3 стадий.
- [ ] Non‑consumption сегменты идентифицированы.
- [ ] Evidence tags расставлены.

Если не пройден чек — доработать.

## 💡 Эвристики Phase 3 (metodolog.ru)

### Анализ условий устаревания (бизнес-риски)
Метод прогнозирования угроз: найдите условия, при которых основная функция системы станет ненужной. Пример: "чистка ковров станет ненужной, если появятся грязеотталкивающие покрытия". Мониторьте рынок на предмет появления таких элементов.

### Anti-pattern: социальный шум
При использовании краудсорсинга и голосований помните: простые системы голосования выводят в топ не самые эффективные идеи, а наиболее популярные. Для фильтрации используйте репутационные механизмы (рейтинг автора зависит от качества его предыдущих идей).
