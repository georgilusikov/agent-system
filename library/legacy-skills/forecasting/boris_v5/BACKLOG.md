# Boris v5 Backlog (base v4.1/4.2)

> Идеи для улучшения системы Boris, собранные по результатам мета-анализа отчётов.
> **Принцип:** Все улучшения должны повышать воспроизводимость и калибровку, а не «оптимизм».

---

## 🔥 High Priority

### 1. Context-fit Score (вместо Adjusted)
**Проблема:** Борис занижает оценки, не учитывая контекст успеха.
**Решение:** Ввести `Raw Score` (универсальный) и `Context-fit Score` (при выполнении условий).
**⚠️ Safeguard:** Context-fit разрешён ТОЛЬКО при:
  - Явно выписанных Success Conditions (контекст/канал/аудитория)
  - Проверяемых метриках/триггерах
  - Минимум 1 эксперимент на валидацию условий
**Фаза:** Phase 5
**Статус:** [x] DONE (v4.1, 2026-01-09)

---

### 2. Аналоги и прецеденты (Benchmark Integration)
**Проблема:** Борис делает выводы «в вакууме».
**Решение:** Обязательная таблица в Phase 2:
  - Минимум 2 аналога
  - Их судьба (успех/провал/pivot)
  - Что переносим / не переносим (в терминах PoA/канала/ограничений)
  - Почему это применимо
**Фаза:** Phase 2
**Статус:** [x] DONE (v4.1, 2026-01-09)

---

### 3. Solution-Scenario Matrix
**Проблема:** Неясно, какое решение работает в каком сценарии.
**Решение:** Обязательная матрица `Решение × Сценарий` с ✅/⚠️/❌ + обоснование.
**Фаза:** Phase 4
**Статус:** [x] DONE (v4.1, 2026-01-09)

---

## 🟡 Medium Priority

### 4. Quick Kill Gate + Pivot Option
**Проблема:** Для мёртвых идей Борис проходит все 6 фаз.
**Решение:** После Phase 0-1:
  - Если нет ценности / hard constraint нарушен → STOP
  - **Но:** STOP всегда с "+ Pivot Option" (если есть очевидный переезд)
**Фаза:** Phase 0-1
**Статус:** [x] DONE (v4.1, 2026-01-09)

---

### 5. Advocate Mode (Контрмеры с ценой)
**Проблема:** AFD ищет способы сломать, но нет механизма спасения.
**Решение:** После AFD — Advocate Pass: 3 контрмеры на каждую диверсию.
**⚠️ Safeguard:** Каждая контрмера ОБЯЗАНА содержать:
  - Ресурс/ограничение, на котором основана
  - Стоимость реализации
  - Влияние на KPI (±%)
  - Тест для валидации
**Фаза:** Phase 5
**Статус:** [x] DONE (v4.1, 2026-01-09)

---

### 6. Confidence Decomposition
**Проблема:** Непонятно, откуда взялся общий Confidence.
**Решение:** Разбивка по компонентам:
  - Качество данных (вес 30%)
  - Логика анализа (вес 30%)
  - Покрытие рисков (вес 20%)
  - Закрытые эксперименты (вес 20%)
**Фаза:** Phase 5
**Статус:** [x] DONE (v4.1, 2026-01-09)

---

## 🟢 Low Priority

### 7. User Feedback Loop (Минимальная версия)
**Проблема:** Борис не обучается на результатах.
**Решение:** В конце отчёта:
  - 1 вопрос: «Через 3 месяца: что из рисков реализовалось?»
  - Чек-лист из 5 пунктов (да/нет)
  - Сохранение в файл `feedback/[idea_name].md` по шаблону `feedback_template.md`
**Фаза:** Output
**Статус:** [x] DONE (v4.2 draft)

---

### 8. Executive Summary Card
**Проблема:** Отчёт слишком длинный для быстрого принятия решений.
**Решение:** Жёсткий шаблон на 1 экран:
  - Идея | Вердикт | Raw Score | Context-fit Score
  - Главный риск (1 предложение)
  - Следующий шаг (1 эксперимент)
**Фаза:** Output
**Статус:** [x] DONE (v4.1, 2026-01-09)
