# 🛡️ Руководство по защите правил от деградации

## 🎯 Проблема

Правила могут ухудшаться при изменениях:
- Удаление важных инструкций "для краткости"
- Упрощение сложных протоколов до нерабочего состояния
- Потеря связей с другими правилами
- Удаление проверок и валидаций

## ✅ Решение

### 1. Протокол защиты (`meta-guard.mdc`)

**Автоматически вызывается:**
- Перед изменением правил
- При триггерах: `[change, modify, update, edit, rewrite, rules, rule]`

**Что делает:**
1. Создает бэкап перед изменением
2. Фиксирует метрики текущего правила
3. Проверяет на деградацию после изменения
4. Сравнивает версии (старая vs новая)
5. Валидирует новое правило
6. Документирует изменения

### 2. Процесс защиты

```
1. ПЕРЕД ИЗМЕНЕНИЕМ
   ↓
   - Создать бэкап (Git коммит)
   - Зафиксировать метрики
   - Определить причину изменения
   ↓
2. ПРИ ИЗМЕНЕНИИ
   ↓
   - Сохранить все важное
   - Проверить на деградацию
   - Сравнить версии
   ↓
3. ПОСЛЕ ИЗМЕНЕНИЯ
   ↓
   - Валидировать правило
   - Протестировать правило
   - Документировать изменения
```

### 3. Красные флаги (СТОП!)

**Немедленно остановись, если:**
- ❌ Удаляешь обязательные инструкции
- ❌ Упрощаешь протокол до нерабочего состояния
- ❌ Удаляешь проверки и валидации
- ❌ Удаляешь ссылки на связанные правила
- ❌ Сокращаешь правило "для краткости" без понимания

**Действия:**
1. ОСТАНОВИСЬ
2. Восстанови из бэкапа
3. Проанализируй причину
4. Создай стандарт или новое правило вместо изменения

```bash

git checkout [commit-hash] -- _agent_shared/rules/[название].mdc
```

```bash
cp _agent_shared/versions/[дата]/[название].mdc \

```

## 📊 Метрики качества

**Отслеживай:**
- Размер правила (строки)
- Количество обязательных инструкций
- Количество ссылок на другие правила
- Количество количественных критериев
- Количество триггеров

**Если метрики резко ухудшились → СТОП и проверь!**

---

## 🎯 Принципы

1. **Бэкап перед каждым изменением** — всегда можно откатиться
2. **Фиксация метрик** — видно, что изменилось
3. **Сравнение версий** — видно, что удалено/добавлено
4. **Валидация** — проверка на работоспособность
5. **Тестирование** — проверка на практике
6. **Документирование** — понимание, почему изменено
7. **Откат** — возможность вернуться назад
