# Hypothesis Eval Loop — before/after доказательство улучшения

Замкнутый цикл: гипотеза → baseline-замер → изменение → повтор той же задачи →
delta → вердикт. Адаптация скилла Красинского (heroes-harness-playbook).
Отличие от /falsify: тот опровергает *один claim* о готовом артефакте; этот
измеряет *эффект изменения* количественно на повторе одной и той же задачи.
Формат карточки гипотезы — [references/03-hypothesis-card.md](references/03-hypothesis-card.md).

## Назначение

Skill нужен когда уже прозвучало:
- `я улучшил скилл/правило — теперь должно работать лучше` (без замера)
- `после правки стало лучше` (на глаз, без baseline)
- `добавим правило и посмотрим` (нет критерия фальсификации)

и надо превратить «выглядит лучше» в подтверждённую или фальсифицированную дельту.

## When to Use
- правка SKILL.md / rules/ / CLAUDE.md / хука при confidence <98%
- «докажи что стало лучше», «прогони before/after»
- регрессия: не сломало ли изменение существующее поведение

## When NOT to Use
- опровергнуть «готово к релизу» end-to-end → /falsify
- найти первопричину уже случившегося падения → /debug
- ранжировать список гипотез → /prioritize

## Input checklist
- [ ] Изменение названо конкретно (какой файл/правило меняем)
- [ ] Есть РЕАЛЬНАЯ задача/инцидент для прогона (не выдуманная и не упрощённая)
- [ ] Задача воспроизводима: тот же input можно прогнать дважды

## Протокол

### §1. Таблица гипотез (ДО любого замера)
| H-ID | Гипотеза | Метрика | Baseline | Target | Критерий фальсификации |
|---|---|---|---|---|---|
| H01 — {кратко} | после изменения X метрика Y улучшится | {имя метрики} | {замерим в §2} | ≤/≥ порог | metric вне target → falsified |

Метрики: число гепов (severity ≥ medium), шагов усилия владельца, pass rate
тестов/триггеров, число инцидентов-регрессий, любая кастомная с описанным источником.
Голая гипотеза без метрики и критерия фальсификации не запускается.

### §2. Baseline — замер БЕЗ изменения
1. `git rev-parse --short HEAD` → зафиксировать SHA baseline
2. Прогнать задачу на текущей системе, собрать метрики из §1
3. Snapshot: SHA + задача + значения метрик + **evidence** (логи, stdout, пути)

**Hard fail:** baseline без evidence. Голое число без пруфа = замера не было.

### §3. Изменение
Внести правку, зафиксировать `git diff --stat` (что именно изменилось) + SHA treatment.

### §4. Treatment — повтор ТОЙ ЖЕ задачи
Та же задача, тот же input, те же метрики. Snapshot в том же формате, что §2.

### §5. Delta-таблица и вердикт
| H-ID | Метрика | Baseline | Treatment | Delta | Verdict |
|---|---|---|---|---|---|

| Условие | Verdict |
|---|---|
| все метрики достигли target | **confirmed** |
| ≥50% достигли, остальные улучшились | **partially confirmed** |
| хоть одна метрика ухудшилась | **falsified** |
| delta ≈ 0 | **falsified** — изменение без эффекта, не «нейтрально» |

### §6. Learning record (обязателен при любом вердикте)
- **confirmed** → merge (или рекомендовать merge), 1 строка в memory/learning loop
- **falsified** → revert (или рекомендовать revert) + альтернативная гипотеза
- **partially** → iterate: уточнить изменение, назад в §3. **Максимум 3 итерации**,
  дальше — эскалация владельцу с delta-таблицами всех попыток

## Definition of Done
- [ ] Таблица гипотез заполнена ДО baseline (метрика + target + фальсификация)
- [ ] Оба snapshot содержат git SHA и evidence
- [ ] Delta-таблица + один вердикт: confirmed / partially / falsified
- [ ] Learning record с действием (merge / revert / iterate)
- [ ] Runnable check: `git log --oneline -2` показывает baseline и treatment состояния

## FORBIDDEN
- Замер baseline ПОСЛЕ внесения изменения (порядок необратим)
- Смена задачи или input между baseline и treatment («на другой задаче лучше» — не eval)
- Вердикт «нейтрально» при delta ≈ 0 — это falsified
- Синтетические значения метрик без evidence — см. `~/.claude/standards/no-fabricated-evidence.md`

## Hard fail
- Нет критерия фальсификации в таблице гипотез → цикл не запускался
- >3 итераций без эскалации владельцу → петля разомкнута
