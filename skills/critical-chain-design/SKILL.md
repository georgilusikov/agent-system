# Critical Chain Design — критическая цепочка Голдратта

Планирование от результата к первому шагу через **одно** ограничение,
вместо inventory list из 15 подзадач. Адаптация скилла Красинского
(heroes-harness-playbook), формат карточки — [references/09-critical-chain-card.md](references/09-critical-chain-card.md).

## Назначение

Skill нужен когда уже прозвучало:
- `вот список из 12 подзадач` (inventory вместо цепочки)
- `всё важно, все P0` (нет constraint)
- `сначала изучим всё, потом решим` (unbounded discovery)

и надо свести план к цепочке 3-5 наблюдаемых звеньев с одним узким местом.

## When to Use
- планирование любой задачи с >2 шагами; «спланируй от конца к началу»
- «какое ограничение?», «где узкое место?»
- подзадачи раздулись >5 штук — переосмыслить через constraint

## When NOT to Use
- сформулировать outcome/выгоду задачи → агент outcome-designer
- отранжировать уже готовый список → /prioritize
- контракт цели и гейты перед делегированием → /goal-plan

## Input checklist
- [ ] Задача названа (что делаем), есть представление о желаемом результате
- [ ] Известно текущее состояние (что уже есть на диске / в проде)
- [ ] Понятно, кто потребитель Output (кому показываем результат)

## Протокол

### §1. Outcome и Output
- **Outcome** = что изменится в мире (одна фраза: `{кто} может {что} без {чего лишнего}`)
- **Output** = конкретный артефакт (файл / API / документ / сообщение)

### §2. Одно ограничение (constraint)
Constraint = **один** ресурс или условие, без которого Output невозможен.
Не список «всего нужного» — одно узкое место. Типы:

| Тип | Пример |
|---|---|
| Данные | нет входных данных для работы |
| Доступ | нет API-ключа, прав, sandbox |
| Знание | непонятна структура / формат / требование |
| Зависимость | блокирован другой задачей |
| Время | дедлайн диктует scope |

### §3. Цепочка от конца
`Output ← {что нужно для Output} ← {что нужно перед этим} ← … ← первый шаг сегодня`.
Каждое звено = **один наблюдаемый артефакт** (не «подумать» / «изучить» / «разобраться»).

**Правило воздуха:** верхнее звено обязано вести к Outcome напрямую, без
недокументированного шага. Есть «воздух» между верхним output и outcome —
добавь недостающее звено.

### §4. Проверка длины
| Шагов | Вердикт | Действие |
|---|---|---|
| ≤2 | слишком грубо | декомпозировать Output на промежуточные артефакты |
| 3-5 | хорошо | продолжать |
| 6-8 | перегруз | вынести параллельные ветки |
| >8 | inventory list | вернуться к §2, переопределить constraint |

### §5. Буфер и сигнал запуска
- **Буфер** = 20-30% запаса времени/scope: что сократить/отложить, если constraint затянется
- **Верёвка** = сигнал, запускающий следующее звено (не раньше, чем нужно)

## Антипаттерны
- **Inventory list** («всё, что надо бы») — нет constraint → назад в §2
- **Fake constraint** («всё важно одинаково») — нет фокуса → найти ONE thing
- **Все P0** — нет последовательности → цепочка, а не матрица приоритетов

## Definition of Done
- [ ] В ответе есть все 6 полей: Outcome, Output, Constraint (ровно один), цепочка 3-5 звеньев, Buffer, сигнал запуска
- [ ] Каждое звено — наблюдаемый артефакт (camera test)
- [ ] Runnable check: `grep -cE "^(Outcome|Output|Constraint)" <план>` ≥ 3

## FORBIDDEN
- Выдавать план >8 шагов без возврата к §2 (это inventory, не цепочка)
- Звенья-глаголы без артефакта («изучить», «подумать», «разобраться»)
- Constraint = «не хватает времени» — это отсутствие приоритизации, не ограничение
- Выдуманное «текущее состояние» без проверки на диске — см. `~/.claude/standards/no-fabricated-evidence.md`

## Hard fail
- Нет явного constraint (или их «несколько равноважных») → план невалиден
- Между верхним звеном и Outcome есть недокументированный шаг («воздух»)
