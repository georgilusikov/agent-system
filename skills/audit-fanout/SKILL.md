# Audit Fanout — мульти-агентный аудит системы

Fan-out N независимых read-only аудиторов по непересекающимся осям дефектов +
синтез. Основан на: /delegate (гейты брифинга), CLAUDE.md §Мульти-агентный аудит
(верификация severity), кейс nikita battle-batch 2026-07-08 (5 осей, cursor мёртв
→ subagent + 3 облачных промта).

## Назначение

Skill нужен когда уже прозвучало:
- `надо проверить систему на ошибки, есть свободные агенты`
- `дай промты для облачного/локального агента на аудит`
- `запусти анализ архитектуры с субагентами`
- `в системе что-то не так, хочу параллельную проверку`

и надо получить не generic-ревью, а находки с file:line по известным классам
дефектов, пригодные для слияния в один план фиксов.

## When to Use

- `аудит с субагентами` / `audit fanout`
- `дай промты для аудита` (режим generate-prompts)
- `сделай анализ системы агентами` (режим run)
- после серии инцидентов одного репо — инвентаризация классов дефектов

## When NOT to Use

- Один артефакт (PR, документ, видео) → `/bouncer`
- Ищем bottleneck процесса/бизнеса, не дефекты кода → `/leverage`
- Причины ОДНОГО бага (линейные или конкурирующие) → `/debug`
- Задача на 1 файл — аудит дороже фикса → просто Read + fix

## Input checklist

- [ ] Известен репо/система и её текущее СОСТОЯНИЕ (что живо, что сломано,
      идёт ли сейчас живой прогон — его папки в запреты!)
- [ ] Есть ≥2 реальных факта об отказах (инцидент, отчёт, memory) для якорей
- [ ] Решён режим: **generate-prompts** (отдать промты пользователю) или
      **run** (раздать субагентам самому)
- [ ] Известно, у каких исполнителей есть доступ к локальным артефактам
      (облако видит только git-репо, локальные runs/ — нет)

## §1. Expected State (до dispatch)

Выпиши до запуска: (a) список файлов-отчётов, которые появятся (один на ось);
(b) acceptance-команда на каждый (обычно `grep -cE "path:[0-9]+" report` ≥ N);
(c) неизменность tracked-файлов (`git status` до = после, только новые отчёты).

## §2. Facts pack — якоря реальности

Собери 3-5 конкретных фактов [O] и вшей их в промты: точные цифры из отчётов,
пути упавших прогонов, известные прошлые инциденты этого репо.

Промт без якоря = generic лекция «пишите хороший код». Якорь даёт аудитору
нить: класс дефекта УЖЕ проявлялся вот здесь — ищи родственников.

Источники: memory (`MEMORY.md` по имени проекта), `docs/audits/`, свежие
отчёты прогонов, git log. Memory протухает — пути проверяй `ls` перед вшиванием.

## §3. Выбор осей и split local/cloud

Оси — в [references/axes.md](references/axes.md) (шаблоны промтов):

| Ось | Что ловит | Нужны локальные артефакты? |
|---|---|---|
| A1 silent-fallbacks | проглоченные ошибки, тихие fake-деградации | нет |
| A2 inert-wiring | producer пишет — consumer не читает; мёртвые флаги | нет |
| A3 deferred-debt | отложенные P1/TODO: живы или починены | нет |
| A4 defect-matrix | таблица падений по РЕАЛЬНЫМ артефактам прогонов | **да** |
| A5 contract-drift | schema/validator vs фактический producer/consumer | нет |
| A6 test-blindspots | fake-путь покрыт, real-путь голый; синтетика маскирует | нет |

Правила выбора:
- Не все 6 всегда. Выбирай по симптомам; 3-4 оси — типовой запуск.
- Одна ось = один агент = один файл отчёта. Оси не пересекаются по файлам-отчётам.
- A4 — только исполнителю с доступом к локальным `runs/`-артефактам; облаку не давать.
- Живой прогон в системе → его папки в ЗАПРЕТЫ каждого промта.

## §4. Сборка промтов (оба режима)

Каждый промт обязан содержать (инварианты из /delegate):
1. **Контекст** — система + 1-2 якоря из §2.
2. **Эталон finding** — заполненный пример формата на реальном якоре.
3. **Запреты** — read-only; один файл отчёта (имя задано); не писать в
   артефакт-папки; не трогать живые прогоны; не запускать пайплайн/тратить
   деньги провайдеров; никаких фиксов.
4. **Задача** — императив, 3-5 шагов, конкретные модули/директории.
5. **Acceptance** — команда, которой отчёт будет проверен (grep-счёт findings
   с file:line, покрытие «все файлы X», git status чист).

**Режим generate-prompts:** выдай промты пользователю блоками для copy-paste,
с пометкой ☁️/💻 и порядком запуска. Стоп — дальше пользователь.

**Режим run:** preflight канала по /delegate §4 (новый канал → тест-задача),
затем dispatch субагентов в фон, по одному на ось. Не дублируй ось, которую
уже взял внешний агент пользователя.

## §5. Синтез после прогона

1. Self-report агента ≠ факт. Прогони acceptance-команды из §1 сам.
2. **Каждый Critical/High — перепроверь Read'ом файла** (агенты завышают
   severity в ~30% случаев — CLAUDE.md §Мульти-агентный аудит).
3. Слей все отчёты в одну таблицу: finding | ось | file:line | severity
   (верифицированная) | подтверждение.
4. Кросс-сверка: статика (A1-A3, A5-A6) vs runtime (A4) — совпадающие seams
   поднимай в ранге.
5. Выбери **ОДИН** bottleneck на фикс. Покажи сводку. **СТОП — жди
   подтверждения перед реализацией.**

## Definition of Done

- [ ] Facts pack: ≥2 якоря [O] с путями, проверенными `ls`/Read
- [ ] Каждый промт содержит секции ЭТАЛОН и ACCEPTANCE
      (runnable: `grep -c "ЭТАЛОН\|ACCEPTANCE" prompt` ≥ 2 на промт)
- [ ] A4 не отдана исполнителю без доступа к локальным артефактам
- [ ] Живые прогоны перечислены в запретах промтов (если есть)
- [ ] Режим run: acceptance-команды прогнаны МНОЙ после завершения агентов
- [ ] Синтез: одна таблица, severity верифицированы, один bottleneck назван
- [ ] Runnable test скилла: `grep -q "^## FORBIDDEN$" SKILL.md`

## Известные грабли

- **Cursor CLI usage limit** (2026-07-08): аккаунт-лимит бьёт ВСЕ модели,
  `--model` не спасает → защита: preflight тест-задача до боевой; fallback —
  свой subagent на локальные оси, облако на статические.
- **Облаку дали ось с локальными артефактами** → агент честно скажет «файлов
  нет» или нафантазирует → защита: §3 split, A4 только локальным.
- **Промт без якоря** → generic-ревью на 50 findings-мусора → защита: §2
  facts pack обязателен.
- **Память дала протухший путь** (AUDIT_BACKLOG не существовал, 2026-07-08) →
  защита: каждый путь в промте проверен `ls` перед вшиванием.
- **Два агента — один файл отчёта** → перезапись → защита: §3 одна ось = один
  файл, имена заданы в промтах.
- **Облако без code-search по приватному репо** (2026-07-08): GitHub connector
  не индексирует приватный репо → все negative-вердикты облака («consumer НЕТ»,
  «producer НЕТ», «TODO нет») недостоверны. Проверено: 2 из 3 спот-чеков
  inert-wiring ОПРОВЕРГНУТЫ локальным grep → защита: A2/A3 negative claims
  облака ре-грепить локально ДО принятия; оси, где вердикт = «отсутствие
  чего-то», предпочтительно давать локальным исполнителям.

## Связанные скиллы

- `/delegate` — протокол брифинга одного исполнителя (этот скилл = N×delegate
  + оси + синтез)
- `check/references/fraud-table.md` — фрод-чеклист для §5 синтеза: отчёт
  аудитора сам проверяется на ложную завершённость и scope creep
- `/bouncer` — внешний аудит одного артефакта
- `/leverage` — bottleneck-карта системы без кода
- `/debug` — когда после синтеза осталось ≥3 гипотезы одного дефекта
- `rules/parallel-agents.md` — если аудиторы что-то ПИШУТ (здесь read-only)

## FORBIDDEN

- Dispatch/выдача промта без секций ЭТАЛОН и ACCEPTANCE
- Отдавать ось A4 (defect-matrix) облачному агенту без локальных артефактов
- Принимать self-report «done» как верификацию — только acceptance-команда
- Представлять severity агентов без перепроверки Critical/High Read'ом
- Фиксить найденное до показа сводки и подтверждения пользователя
- Выдумывать результаты acceptance-команд — см.
  `~/.claude/standards/no-fabricated-evidence.md`

## Hard fail

- Промт позволяет агенту писать вне его файла-отчёта → не read-only аудит
- Сводка без верификации severity → транслирование чужого вывода как факта
- Названо >1 bottleneck'а «на фикс первым» → синтез не выполнен
