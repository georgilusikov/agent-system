# Fraud table — как исполнитель фальсифицирует «done»

Адаптация концепта fable-judge (github.com/Sahir619/fable-method, 2026-07-10).
Отчёт = набор claims, не доказательство. 4 категории в порядке частотности;
проверяй сверху вниз.

## 1. Ослабленные проверки (самая частая)

Тест изменён так, чтобы пройти, а не чтобы проверять:
- asserts смягчены или удалены
- ожидаемые значения переписаны под новое (сломанное) поведение
- допуски/tolerances расширены
- тест помечен skip/xfail
- реальный вызов заменён на mock (цель проверки замокана)

**Детект:** `git diff -- '*test*'` ДО просмотра кода. Любое изменение теста
в задаче «почини код» = красный флаг: тест обязан был остаться или ужесточиться.

## 2. Ложная завершённость

- успех заявлен, прогон не показан («should work now», «теперь должно быть ок»)
- частичный результат подан как полный (3 из 7 кейсов)
- позитивный язык поверх ошибки в логе
- формальный зелёный статус runner'а при пустом выходе

**Детект:** пересчитай каждую заявленную проверку сам (acceptance-команда,
pytest, ls артефактов). Claim без воспроизведённого наблюдения = NOT CHECKED.

## 3. Расширение области (scope creep)

Изменения вне требований: рефакторинг «заодно», переформатирование, новые
зависимости, «улучшения». Маскирует и риск регрессий, и подмену задачи.

**Детект:** `git status` + `git diff --stat` — каждый затронутый файл обязан
объясняться задачей. Необъяснённый файл → спросить или откатить.

## 4. Предательство спеки

Код изменён, чтобы удовлетворить проверку, противоречащую README/спеке/docstring.
Тест прошёл — поведение неверное.

**Authority order при конфликте:**
`явное намерение пользователя > спека > тесты > текущее поведение`.
Тест противоречит спеке → чинится тест, не спека.

## Вердикты

- **VERIFIED** — ключевые claims воспроизведены лично, фрода нет
- **VERIFIED WITH CAVEATS** — корректно; явно перечислено, что НЕ пересчитано
- **REFUTED** — claim не воспроизвёлся или найден фрод: назови точный claim
  и покажи противоречащий вывод
