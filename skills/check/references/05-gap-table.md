# Шаблон: Gap Table (Expectation vs Reality)

> Каноничная таблица для фальсификации гипотезы / проверки доставки.
> Источник: heroes-harness-playbook, `templates/05-gap-table.md` (адаптация).

## Минимальные колонки (mandatory)

| # | Expectation | Reality | Δ | Severity | Verdict | Next action | Усилие человека (0-100) |
|---|---|---|---|---|---|---|---|

7 колонок. Меньше — нарушение формата.

## Семантика колонок

| Колонка | Что в неё писать |
|---|---|
| `Expectation` | Что должно быть истинно, если гипотеза верна. С макросом `E01 — что проверяем` |
| `Reality` | Что фактически наблюдается на диске / в продукте / в данных. Со ссылкой на источник |
| `Δ` | Разница в человекочитаемой форме. Не «не соответствует» — а «ожидали 95%, получили 78%, минус 17 п.п.» |
| `Severity` | `critical` (блокирует доставку) / `high` (исправить до closure) / `medium` (в follow-up) / `low` (информационно) |
| `Verdict` | `match` / `partial` / `falsified` |
| `Next action` | Конкретное действие, если `partial` или `falsified`. С макросом `G01 — что чинить` |
| `Усилие человека (0-100)` | Шкала усилия владельца: 0 = полная автоматизация; 10 = один клик «approve»; 20 = выбор из 2-3 готовых вариантов; 50 = **минимум за любой клик/открытие документа/переключение контекста**; 70 = ручное расследование; 90-100 = переделка |

## Минимальный размер

**Минимум 2 содержательные строки.** Декоративная одна строка «всё OK» не считается.
Если действительно одна проверка — добавь explicit «нет других проверок» с обоснованием.

## Финальный verdict (под таблицей)

```
verdict: confirmed | partially confirmed | falsified
```

- `confirmed` — все строки `match`
- `partially confirmed` — есть `partial`, но все `next action` готовы и плановые
- `falsified` — есть `falsified` строки → доставка заблокирована, идти на re-implementation

При `partially confirmed` или `confirmed` — прогнать вывод через лестницу
so-what (L0 действие / L1 checkpoint / L2 outcome — /check §4.5, /pizdej §So-What).

## Worked example

```
| # | Expectation | Reality | Δ | Severity | Verdict | Next action | Усилие человека (0-100) |
|---|---|---|---|---|---|---|---|
| 1 | E01 — README содержит структуру репо | README.md есть, структура есть | — | low | ✅ match | — | 0 |
| 2 | E02 — все 18 скиллов скопированы | `ls skills/` = 18 файлов | — | low | ✅ match | — | 0 |
| 3 | E03 — initial commit запушен | `git log` = 1 commit, `git push` не сделан | push pending | high | ⚠️ partial | G01 — запушить до closure | 10 (один git push) |

verdict: partially confirmed
next-action digest: G01 — запушить → 10 единиц усилия владельца
```

## Anti-patterns

- ❌ Колонки `Severity` и `Verdict` объединены в одну
- ❌ Отсутствует `Усилие человека (0-100)` — нарушение mandatory-формата
- ❌ `Δ` = «не совпало» вместо конкретной разницы
- ❌ В `Reality` нет источника (где это видно?)
- ❌ Verdict под таблицей отсутствует или нечёткий («вроде ОК»)
