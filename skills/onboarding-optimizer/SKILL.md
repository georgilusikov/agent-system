# Onboarding Optimizer

## Quick start
Предоставь раскадровку первой сессии (от входа до целевого действия),
сегментацию и аналитику. Агент проведёт 4-шаговый аудит онбординга.

## Workflow

### Шаг 1: JTBD-сценарии
Выпиши сценарии, ради которых пользователи приходят:
- Когда пользуется сервисом? (утро/вечер/выходные)
- Какова цель? (быстро/дешево/разнообразно)
- Для кого? (для себя/семьи/гостей)

### Шаг 2: Сегментация по ожиданиям
- **Базовые (Paradigm)** — то, что ожидается по умолчанию (не рекламируй)
- **Специфичные** — уникальные ценности продукта (подчеркивай)
- **Страхи и барьеры** — что вызывает сопротивление (обрабатывай)

### Шаг 3: Анализ раскадровки
Для каждого экрана проверяй:
- [ ] Привлекает внимание? Понятна выгода?
- [ ] Данные запрашиваются обоснованно и вовремя?
- [ ] Обучение про пользу, а не про фичи?
- [ ] Понятно, что делать дальше?

### Шаг 4: Проверка на типичные ошибки
- [ ] Нет ценности на первом экране
- [ ] Необоснованный запрос данных
- [ ] Формальный скучный онбординг (кнопка «Пропустить» = маркер)
- [ ] Рассказ о фичах вместо пользы
- [ ] Потеря трафика на этапах онбординга
- [ ] Необработанные возражения
- [ ] Проблемы Discovery в каталоге (Catalog-to-Cart < 2%)

## Output format
```
## Анализ Онбординга: {продукт}
### Сценарии использования
### Анализ по этапам
  Этап N: Оценка X/10, проблемы, решения
### Типичные ошибки: найдено / не найдено
### Итоговая оценка: средний балл, критические проблемы
### Метрики: текущее → целевое
```

## Формулы
- **Onboarding Quality** = (Attention + Interest + Clarity + Value + Trust) / 5
- **Catalog-to-Cart** = Переходы в корзину / Просмотры каталога (< 2% = проблема)
- **Learning Tax** = (Обучение + Понимание UI) / Общее время (> 30% = слишком сложно)

## Чек-лист качества
- [ ] Выписаны JTBD-сценарии
- [ ] Определена сегментация ожиданий
- [ ] Проанализирован каждый экран раскадровки
- [ ] Проверены все 7 типичных ошибок
- [ ] Оценка по 5 критериям (1–10)
- [ ] Конкретные рекомендации с приоритетами
- [ ] Метрики для проверки гипотез

## Key principles
- **Ошибка пользователя = ошибка дизайнера** — тестируй, не обвиняй
- **User-Centric, не Feature-Centric** — говори про пользу, не про фичи
- **Минимизируй Cycle Time** — быстрее до первой ценности = выше активация
- **Учёт сегментов** — разные ожидания у разных сегментов
- **Итеративный процесс** — MVP гайда → тест → улучшение
