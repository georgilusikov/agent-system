# Debug — RCA: одна цепочка или таблица гипотез

Бывшие `/why` + `/triage` (merge 2026-07-10, golden-set PASS). Один вход,
развилка внутри.

## Режим-роутер (первый шаг, обязательный)

- **Одна линейная цепочка** (точный traceback, ясный симптом) → Mode L.
- **≥3 конкурирующих причины** (flaky, race, «то падает то нет», multi-cause) → Mode H.
- 2 гипотезы / бинарный выбор → `/anti-bias`. Проблема не сформулирована → `/leverage`.
- В Mode L на любом «почему» выросло ≥3 ПАРАЛЛЕЛЬНЫХ ветки → переключись в Mode H;
  вернись в L с top-гипотезой posterior ≥80%.

## Anti-freeze (оба режима)

Freeze-сигнал: та же попытка 3+ раз / timeout / killed / retry без нового evidence →
STOP. Зафиксируй таблицу: last known good state, last failed attempt, unknown —
каждая строка с местом подтверждения. Затем ОДИН новый probe, меняющий информацию
(минимальный repro, verbose log, grep, isolation run, version/permissions check).
Пока probe не выполнен — его результат `NEEDS PROBE`, не факт.
Следуй `standards/no-fabricated-evidence.md`.

## Петля обратной связи (шаг 0, оба режима)

**Это и есть навык, остальное механика.** Есть быстрый детерминированный
pass/fail-сигнал, краснеющий ИМЕННО на этом баге — причина найдётся: бисекция,
проверка гипотез и инструментирование только потребляют этот сигнал. Сигнала нет —
сколько ни смотри в код, не поможет. Вкладывайся сюда непропорционально много.

Способы построить, примерно в этом порядке: **падающий тест** на подходящем шве
(unit/integration/e2e) → **curl/HTTP-скрипт** по живому dev-серверу → **CLI на
фикстуре** с диффом stdout против known-good снапшота → **headless-браузер**
(Playwright/Puppeteer) с ассертом на DOM/console/network → **реплей захваченного
трейса** (реальный запрос/payload/event log на диск, прогон через код в изоляции) →
**одноразовый harness** (минимальный кусок системы, один вызов функции по багованному
пути) → **property/fuzz-петля** («иногда неверный выход» → 1000 случайных входов) →
**harness для бисекции** (баг появился между двумя известными состояниями → автоматизируй
«поднять X, проверить, повторить» под `git bisect run`) → **дифференциальная петля**
(один вход через старую и новую версию, диффать выходы) → **HITL-скрипт** последним
средством: кликать должен человек — веди ЕГО скриптом, чтобы петля осталась структурной.

**Затягивай петлю** как продукт: быстрее (кэш setup, пропуск лишней инициализации,
сузить scope теста), сигнал острее (ассерт на конкретный симптом, а не «не упало»),
детерминированнее (пин времени, seed RNG, изоляция ФС, заморозка сети). 30-секундная
флейки-петля почти не лучше отсутствия петли; 2-секундная детерминированная —
сверхспособность. Правильная петля = баг починен на 90%.

**Недетерминированный баг:** цель не чистое repro, а **более высокая частота
воспроизведения**. Гоняй триггер 100×, параллель, стресс, сужение тайминговых окон,
инъекция sleep'ов. 50% флейка отлаживается, 1% — нет; поднимай частоту до отлаживаемой.

**Петлю построить не удалось** → скажи это явно, перечисли что пробовал, и запроси у
владельца: доступ к среде, где воспроизводится / захваченный артефакт (HAR, дамп логов,
core dump, запись экрана с таймкодами) / разрешение на временное инструментирование
в проде. Выдвигать гипотезы без петли — запрещено.

## Mode L — линейная цепочка (5 Whys)

1. **Факты:** точная ошибка, команда, полный output/traceback.
2. **5 Whys:** каждое «почему» опирается на наблюдение из файла/лога/коммита/команды.
   Нет evidence → `NEEDS PROBE`, цепочку догадками не дописывай.
3. **Fix.** Chesterton fence: fix удаляет/обходит существующий код, гейт, конфиг →
   сначала «зачем это было построено?» с evidence (`git log -5 --oneline -- <file>`,
   blame, memory-инцидент). Причины не нашёл → НЕ удаляй, спроси владельца.
   Свежий коммит той же недели = вероятно намеренное решение.
   Исправляй корневую причину, не симптом; точечные правки; никаких обходных
   путей «на 99% уверен» — проверь предположение данными до фикса.
4. **Verify:** повтори команду, вызвавшую ошибку.
5. **Document:**

```
Command / Error / Root Cause / Fix
Status: Verified | Still failing | Needs probe
```

`Verified` — только после реального повторного прогона.

6. **Redo:** после RCA — в том же ходе переделай исходную задачу; RCA без redo = незакрытый инцидент.
7. **Prevention-ветка («Как это могло НЕ произойти?»):** после 5 Whys разверни 4 ветки —
   авто-гейт/хук; метрика-алерт; peer review; явный запрет в правиле — и выбери одну design injection.

## Mode H — конкурирующие гипотезы (Bayes-таблица)

Input checklist: ≥3 гипотезы (застрял на 2 = anchoring, думай ещё); у каждой —
класс систем для prior; есть source-of-truth; есть ≥1 discriminating test на пару.

Flaky/race routing: `flaky` → обязательные гипотезы race / fixture state / network /
timezone / order-dependence. `race`/shared state → первый probe различает timing vs
state leakage.

1. **Таблица (все колонки):**

| # | Гипотеза | Prior | Evidence за | Evidence против | Discriminating test |
|---|---|---|---|---|---|

- Prior = base rate класса систем, не этого инцидента; неизвестен → `?` + диапазон.
- Evidence — только `[O]bserved`; логи не читались → `NOT CHECKED`, posterior не трогать.
- Discriminating test различает ЭТУ гипотезу от соседней; «подтверждает все» ≠ discriminating.

2. **Первый тест:** max информация / min затраты. Cheap+high-discriminating → first.
   Запиши явно: «Первый тест: X — различает H1 от H2 за 5 минут».
3. **Bayes update:** falsified → вычеркни; supported → posterior ≈ prior × likelihood;
   inconclusive → другой тест. ВСЕ falsified → пропущен вариант, пересмотри frame.
4. **Стоп:** одна гипотеза posterior ≥80% И прошла discriminating test — ИЛИ evidence
   достаточно для действия. Запрет: стоп на posterior <60% «интуитивно».
5. **Output contract:** таблица 3+ строк, prior у каждой, discriminating tests top-2,
   выбор первого теста с обоснованием, «Уверенность в top гипотезе: X%».

## Handoff (оба режима)

- Fix применён → `/check` (верификация + регрессии). High-stakes/prod → `/falsify`.
- Root cause процессная/повторяемая → `~/.claude/bin/log-incident.sh --kind rca
  --severity medium --source /debug --summary "..."`.

Эталон вывода (Mode L, полный контракт): `examples/golden_basic.md`.

## FORBIDDEN

- Придумывать результаты grep/тестов/логов/содержимое файлов.
- `Verified` без повторного прогона команды.
- Гипотеза как root cause без evidence; posterior update без прочитанного evidence.

## Hard fail

- Invented evidence. `Status: Verified` без прогона. Mode H без таблицы с prior.
