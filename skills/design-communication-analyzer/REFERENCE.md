# Design Communication Analyzer — Полный справочник

## Подробная методология

### Шаг 1: Определить авторское намерение

**Задача**: Понять, что хотел сказать автор дизайна.

**Метод «Method of Propositions» (Светодиодное освещение)**:
> Сначала ограничиться в дизайне единственным инструментом — предложениями. Что бы вы сказали человеку, если бы были рядом, вместо страницы сайта?

**Алгоритм**:
1. Возьми макет/скриншот
2. Спроси себя: «Что автор пытается сказать?»
3. Сформулируй сообщение в одном предложении
4. Проверь: способствует ли дизайн этому сообщению?

**Свойства метода**:
- **Вправляет мозги**: Если не можешь описать страницу текстом — значит не понимаешь задачу
- **Совместимость с ФФФ (First F***ing Feature)**: Первый результат готов за полчаса. Далее текст «обрастает» дизайном, иллюстрациями и интерактивом, но в любой момент страница готова к публикации

**Пример: калькулятор экономии ламп**

Вместо сложного интерфейса с ползунками:
1. Светодиодные лампы выгоднее, хоть и дороже ламп накаливания. (Раскрываем противоречие)
2. Они потребляют в 10 раз меньше электроэнергии и служат в 5 раз дольше. (Объясняем механизм)
3. Приводим конкретный расчёт: за 5 лет экономия больше 2000 р. на одну лампу.

**Динамизация**: Когда текст готов, можно сделать цифры переменными (интерактивными), превращая текст в калькулятор.

**Ключевой вопрос**: Какую проблему пользователя решает этот дизайн?

### Шаг 2: Проверить синтаксис дизайна

**Элементы дизайна имеют синтаксические роли**:
- Заголовок — тема/глагол
- Акцентный цвет — призыв к действию
- Иерархия — порядок прочтения
- Группировка — связанные концепции

**Проверь**:
1. Есть ли ясный визуальный акцент?
2. Понятен ли порядок прочтения?
3. Согласованы ли размер, цвет, позиция элементов с их ролью?

**Типографика заголовков**:
- **Визуальный контраст**: Жирный шрифт не обязателен для крупных заголовков, но нужен для контраста с мелким текстом
- **Многострочные заголовки**: Избегай висячих союзов/предлогов, переносы должны помогать пониманию смысла
- **Правило внутреннего и внешнего**: Расстояние от заголовка до его текста (внутреннее) < расстояния до предыдущего блока (внешнее)

### Шаг 3: Оценить когнитивную нагрузку

**Посчитай количество объектов**:
- Кнопки
- Поля ввода
- Текстовые блоки
- Изображения
- Иконки

**Правило**: Каждый объект — это когнитивная нагрузка.

**Цель**: Минимизировать количество объектов при сохранении функциональности.

### Шаг 4: Проверить «Design as Text»

**Дизайн — это всегда сообщение.**

**Вопросы для проверки**:
1. Если бы дизайн был текстом, что бы он говорил?
2. Есть ли противоречие между формой и содержанием?
3. Усиливает ли форма сообщение или ослабляет его?

### Шаг 5: Найти скрытые задачи

**99% задач поставлены неверно.**

**Assumption Testing**:
1. Выпиши все предположения в задаче
2. Найди когнитивные искажения
3. Сделай assumption_smasher.md
4. Найди корневую проблему

## Примеры из курса

### Плохой пример (энергосберегающие лампы)
- **Сообщение**: «Светодиодные лампы выгоднее»
- **Проблема**: 20+ объектов, перегруженный интерфейс, нет ясного акцента
- **Результат**: Пользователь не понимает выгоду

### Хороший пример (11Labs)
- **Сообщение**: «Создавай голоса прямо сейчас»
- **Решение**: Активация на лендинге без регистрации
- **Ключевые элементы**: Голоса, переключалка сценариев, проба прямо на экране

### Форма оплаты (Stripe)
- **Сообщение**: «Оплати в один клик»
- **Решение**: Группировка полей в один объект (card number, expiry, security code)
- **Результат**: 7 объектов вместо 20+

## Чек-лист качества
- [ ] Авторское сообщение сформулировано ясно
- [ ] Визуальная иерархия понятна
- [ ] Количество объектов минимизировано
- [ ] Форма усиливает сообщение
- [ ] Проверены assumptions задачи

---

## Формулы
- **Cognitive Load** = Количество объектов на экране
- **Activation Rate** = (Пользователи, совершившие целевое действие) / (Пользователи, увидевшие экран)

---

## Принципы
1. **Меньше интерфейса — лучше**: Убирай, а не добавляй
2. **Дизайн — не искусство**: Это коммуникация с целью
3. **Порядок действий важен**: Buildorder определяет результат
4. **Ответственность берут**: Сеньор говорит «нет» некачественной задаче
5. **Проверяй данные**: Верить действиям, не словам
