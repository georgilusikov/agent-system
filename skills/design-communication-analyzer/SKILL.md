# Design Communication Analyzer

## Быстрый старт
Получи макет/скриншот → определи авторское сообщение → проверь синтаксис → оцени нагрузку → найди скрытые задачи.

> **⚠️ AI-анализ**: Для шага 2 (синтаксис дизайна) визуальный скриншот ОБЯЗАТЕЛЕН. Текстовый скрапинг пропускает визуальную структуру, атрибуцию отзывов, цены, sticky-элементы. Помечай находки: [ВИЗУАЛ ✓] или [ТОЛЬКО ТЕКСТ ⚠️].

## Входные данные
- Скриншот или описание интерфейса
- Цель экрана (если известна)
- Описание целевой аудитории

## Рабочий процесс

### Шаг 1: Определить авторское намерение
- [ ] «Что автор пытается сказать?» — сформулировать в одном предложении
- [ ] Метод предложений: что бы вы сказали человеку вместо страницы сайта?
- [ ] Какую проблему пользователя решает этот дизайн?

### Шаг 2: Проверить синтаксис дизайна
- [ ] Заголовок = тема, акцентный цвет = призыв к действию
- [ ] Ясный визуальный акцент? Понятен порядок прочтения?
- [ ] Размер/цвет/позиция согласованы с ролью элементов?
- [ ] Типографика: контраст, переносы, внутреннее < внешнее расстояние

### Шаг 3: Оценить когнитивную нагрузку
- [ ] Посчитать объекты: кнопки, поля, тексты, изображения, иконки
- [ ] Каждый объект = когнитивная нагрузка → минимизировать

### Шаг 4: Проверить «Design as Text»
- [ ] Если бы дизайн был текстом — что бы он говорил?
- [ ] Есть ли противоречие формы и содержания?
- [ ] Форма усиливает или ослабляет сообщение?

### Шаг 5: Найти скрытые задачи (Assumption Test)
- [ ] Выписать все предположения команды о пользователе
- [ ] Найти когнитивные искажения: Authority Bias, Anchoring, Social Proof без верификации, Quantity Bias
- [ ] Найти корневую проблему: что команда считает очевидным, но пользователь не знает?

## Формат вывода

```
## Анализ дизайна как коммуникации

### Авторское сообщение
{одно предложение}

### Синтаксис дизайна
- Визуальный акцент: {что привлекает внимание первым}
- Порядок прочтения: {1 → 2 → 3}
- Группировка: {как объекты объединены}

### Когнитивная нагрузка
- Количество объектов: N | Оценка: Низкая/Средняя/Высокая

### Проблемы коммуникации + Рекомендации
### Assumption Test (таблица)
```

## Ключевые принципы
- **Меньше интерфейса — лучше**: убирай, а не добавляй
- **Дизайн — не искусство**: это коммуникация с целью
- **Порядок действий важен**: buildorder определяет результат
- **Ответственность берут**: сеньор говорит «нет» некачественной задаче
- **Проверяй данные**: верить действиям, не словам

## Формулы
- **Cognitive Load** = количество объектов на экране
- **Activation Rate** = действия / показы
