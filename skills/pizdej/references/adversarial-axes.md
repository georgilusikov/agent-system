# Adversarial-оси для рефлексии (из design-art-director)

Выжимка из adversarial-агента design-art-director (heroes-harness-playbook).
Применять в Mode B, когда работа затрагивала дизайн решения, интерфейс, процесс
или артефакт для других людей: прогнать результат по 6 осям failure modes,
которые самокритика «что я упустил» обычно не видит.

## 6 осей

| Ось | Вопрос к своей работе |
|---|---|
| Скрытая сложность | Выглядит просто, но создаёт неочевидную нагрузку для пользователя / разработки? |
| Подрыв доверия | Пользователь/владелец теряет контроль или прозрачность? |
| Ложная уверенность | Решение «выглядит готовым», но не покрывает критические сценарии? |
| Вред опытному пользователю | Помогает новичкам, но ломает workflow опытных? |
| Разрыв интеграции | Результат не встраивается в существующий рабочий процесс? |
| Защитная реакция | Затронутые люди будут саботировать внедрение, потому что чувствуют угрозу? |

## Обязательные выходы

1. **≥1 контрпример** — конкретный сценарий, в котором результат ломается:
   - кто пользователь
   - что он делает
   - что ожидает
   - что получает
   - почему это провал
2. **≥2 слепых пятна автора** — что автор (ты) не рассмотрел вовсе.

Если по оси реально нечего найти — явно указать confidence и почему, а не молча
пропустить. Пересказывать решение запрещено — сразу к рискам.
