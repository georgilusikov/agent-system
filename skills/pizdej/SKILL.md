# Протокол "Пиздёж"

Два режима, одна цель — убрать самообман до того, как он дойдёт до владельца.
Выбор по триггеру: **собираешься ОТЧИТЫВАТЬСЯ → Mode A**; работа ЗАКОНЧЕНА и
подозреваешь пробелы → **Mode B** (§0-§3 ниже). Сложная задача, завершившаяся
сильным утверждением, требует обоих.

## Mode A — Claim Integrity (перед отчётом)

1. Выпиши все утверждения, которые собираешься заявить.
2. К каждому — точное evidence: путь к файлу + строка/ключ; команда + результат;
   путь к артефакту; вывод теста; принятая инструкция владельца.
3. Попробуй фальсифицировать каждое:
   - протухшее / существовало до тебя? только на фикстуре? тест уже claim'а?
   - инертная схема/отчёт, у которых нет потребителя?
   - успех транспорта выдан за успех суждения?
   - overclaim про publish / качество / готовность?
   - противоречит более свежему source of truth?
4. Неподтверждённые утверждения — убрать или понизить.
5. В финальный ответ идут только выжившие утверждения + явные остаточные риски.

```text
PIZDEJ_CLAIMS
claims:
- claim: / evidence: / falsification_attempt: / status: verified|downgraded|removed
removed:
residual_risks:
```

**Guardrails Mode A:** успех транспорта ≠ успех суждения · числовой скор ≠ одобрение
владельца · зелёные тесты — evidence только для того поведения, которое они реально
покрывают · вопрос про верификацию результата → остановись и иди в `/check`.

## Mode B — Process Reflection (после сложной работы)

Работа затрагивала дизайн решения / артефакт для других людей → прогнать по 6 adversarial-осям: [references/adversarial-axes.md](references/adversarial-axes.md).

## 0. Самодиагностика

Ответь честно:

- Что ты НЕ учёл? Что не нашёл, что не сделал?
- Какие ошибки допустил?
- Какой deep research кода или output НЕ сделал?
- Какие вопросы себе не задал?

Не цитируй MEMORY, incidents, файлы или логи, если не читал их в этой сессии. Пиши `NOT CHECKED` и следуй `standards/no-fabricated-evidence.md`.

### Context Rot

Если ≥10 сообщений И повторяешь уже известные факты, ИЛИ перечитываешь тот же файл 3+ раза, ИЛИ первая задача сессии не видна в последних 5 сообщениях → `/clear` + handoff.

### Tickle the Latent Space

Если инструкция длиннее 3 абзацев на один шаг, или ты перечислил >7 пунктов чеклиста без действия — сократи до 3-5 минимально достаточных зацепок.

### Back Pressure

Перечисли 2 конкретных момента, где ты усомнился в первоначальной гипотезе и перепроверил. Если не можешь — значит ехал по инерции, вернись к фактам.

## 1. Gap / Design Injection

Не смягчай самокритику, но переведи её в усиление системы:

- Какой gap в rule/standard/skill/process позволил ошибке пройти?
- Где должна быть design injection: `CLAUDE.md`, `rules/`, `standards/`, конкретный `skills/*/SKILL.md`, script/hook?
- Какая одна строка или короткая секция предотвратит повтор?
- Эта строка предотвращает incident, снижает усилие, повышает вероятность правильного результата или делает ошибку наблюдаемой?
- Нужен incident? Да, если gap `medium+`, повторный, связан с missed memory/check, false done, false PASS или user correction.

Если нужен incident:

```bash
~/.claude/bin/log-incident.sh --kind skill-gap --severity medium --source /pizdej --summary "Короткий redacted summary"
```

## 2. Калибровка уверенности

**Уверенность: [до]% → [после калибровки]% — [причина корректировки]**

## 3. После рефлексии

Если были изменения в коде — переходи к верификации через skill `check`.
Если найден системный gap — patch по `standards/scope-rewrite-policy.md`, затем `/check`.

## FORBIDDEN

- Пустое «всё ок» в §0 — если реально нечего добавить, покажи ГДЕ искал (файлы/шаги)
- Цитировать MEMORY/incidents/логи, не читанные в этой сессии (пиши `NOT CHECKED`,
  см. `~/.claude/standards/no-fabricated-evidence.md`)
- Самокритика без Design Injection §1 — «я ошибся» без строки-усиления системы = ритуал
- Логировать incident на каждую мелочь — только gap `medium+` / повторный / false done

## Hard fail

- Нет ответов на вопросы §0 (или ответы-заглушки) → рефлексия не состоялась
- Есть gap `medium+` но нет Design Injection точки (file → section → text) → петля разомкнута
- Нет калибровки уверенности → output невалиден

## So-What: claim про результат — outcome или checkpoint

Каждый claim вида «сделано / готово / работает» прогнать через «и что с того для
следующего оператора?»:

- **L0 — действие** (файл создан, коммит сделан) — не результат;
- **L1 — checkpoint** (тест зелёный, PR создан, страница открывается) — не результат,
  задать «и что?» ещё раз;
- **L2 — outcome** (ручной шаг исчез, поведение изменилось, цикл короче) — результат.

Claim, застрявший на L0/L1 и поданный как результат, — это пиздёж по форме «сделал» вместо
«изменилось». Понизить до факта действия и дописать, какой outcome ещё НЕ достигнут.
