# AGY Video RCA Standard v0.0.1

Конвейер: отсмотр роликов ролями → каталог симптомов → RCA с привязкой к коду →
дедуп → арбитраж по checkout → один bottleneck → внешняя верификация (Codex).
Главный принцип: **смотрящий не объясняет, объясняющий не смотрит** — стадии разделены.

## Job-to-be-done сценарии

- **Отрендерен новый батч** (первый или после фикса) → полный конвейер §1-§5.
- **AGY уже выдал список RC** → входишь со стадии §3 (дедуп) + §4 (арбитраж).
- **Спор «чинить X или Y первым»** → §4.3 критерий выбора bottleneck.

## Точка G (бинарные критерии)

- [ ] Каталог симптомов существует: каждая строка = {видео, таймкод, наблюдение} без слова «потому что»
- [ ] Каждый RC имеет file:line ИЛИ помечен UNVERIFIED
- [ ] Таблица дедупа: каждая исходная метка присвоена ровно одному корню
- [ ] Каждый корень имеет вердикт ЖИВ/МЁРТВ с evidence из текущего checkout
- [ ] Выбран ОДИН bottleneck с offline acceptance-командой (без провайдеров/рендера)
- [ ] Отчёты лежат в `docs/reports/<batch>/` репозитория, не только в brain-директории AGY
- [ ] Codex-верификация отправлена по брифу /delegate (эталон + запреты + acceptance)

## Методология

### §1. Запуск отсмотра (AGY teamwork preview)

Канал: teamwork preview — ok, работает. Альтернативы (CDP dispatch, backlog) — см.
скилл `/known-symptom-fixes` §4 (бывш. `rules/antigravity-cdp.md`). Обязательно в промпте:

- **Артефакты — в репо:** `пиши все отчёты в docs/reports/<batch-name>/`, не в brain.
  Brain-директории (`~/.gemini/antigravity/brain/{uuid}/`) непроходимы после сессии.
- **Стадия 1 = только симптомы.** Запрет на причины, гипотезы, фиксы. Формат строки:
  `{видео} | {таймкод} | {наблюдаемое, camera test} | {severity 1-3 субъективно}`.
- Один прогон = один батч = одна директория отчётов.

### §2. Семь ролей отсмотра

| Роль | Смотрит | Ловит |
|---|---|---|
| Silent viewer | без звука | субтитры: дыры, микро-cue, читаемость, safe area |
| Слушатель | без картинки | TTS-интонация, язык, mix, повторы SFX |
| Целевой зритель | как есть, телефон | скука, момент выключения, CTA |
| Visual-критик | картинка vs текст | нерелевантные ассеты, дубли, склейки |
| Языковой пурист | язык всего | утечки не-целевого языка (субтитры/озвучка/ассеты) |
| QC-инженер | qc_full_report vs глаза | расхождение гейта и реальности = дефект гейта |
| Продюсер | публиковал бы? | первое отталкивающее, product-блокеры |

QC-инженер — единственная роль с доступом к JSON-отчётам. Остальные — только видео.

### §3. RCA + дедуп (второй прогон, отдельный промпт)

Вход: каталог симптомов + доступ к репо. Требования к каждому RC:

- механизм: симптом → код-путь → file:line. Нет file:line → пометка UNVERIFIED.
- **negative claims («X не используется», «файла нет») не принимаются без `rg`** —
  на battle-batch-20260708 два таких опровергнуты локальным поиском.
- Затем дедуп-таблица: N меток → корни. Метка = симптомокомплекс, корень = seam кода.
  Ожидай сжатие ~2x (18 → 8).

### §4. Арбитраж по коду (Claude или Codex, read-only)

#### 4.1 Верификация корней
Каждый корень → ЖИВ/МЁРТВ против **текущего** checkout (код мог измениться после
отсмотра): Read файла, не память. Severity мульти-агентов завышена в ~30% случаев —
все P0/P1 перепроверять лично.

#### 4.2 Обязательный вопрос: дефект зрителя или артефакт метрики?
Для каждого числового гейта (coverage, balance, WPM): прочитай И расчёт метрики,
И рендер-consumer. Пример: caption coverage 75% стал реальным дефектом только после
проверки, что рендерер вставляет blank-кадры между фразами.

#### 4.3 Выбор bottleneck (один)
Критерий: `частота по роликам × детерминизм доказательства × дешевизна proof-loop`.
Детерминированная метрика из QC-json бьёт мнение роли. Фикс должен доказываться
offline (без TTS/stock/рендера) — иначе выбери другой первый шаг.

#### 4.4 Перед новым кодом — лестница ИКР
`rg` по репо: существующий модуль/repair-путь уже умеет нужное? (кейс:
`caption_overlay_reflow.py` существовал, но не был подключён к основному pipeline).

### §5. Внешняя верификация и план

Бриф для Codex строго по `/delegate`: эталон строки вердикта → запреты → задача →
acceptance. Codex — верификатор, не кодер. После его вердикта — ACTION_PLAN с
trade-off таблицей вариантов фикса. Acceptance-команды прогоняешь сам.

## Принятые решения

- Отсмотр и RCA — раздельные прогоны, не один промпт — иначе роли галлюцинируют причины.
- Повторный отсмотр тех же роликов не запускать: симптомное поле насыщается за 1-2
  прохода. Перезапуск — только после ре-рендера или на новом контенте.
- Отчёты — в репо, brain-директория = черновик.

## Известные грабли (battle-batch-20260708)

- 18 RC без дедупа выглядели как 18 задач: → защита: §3 дедуп-таблица до приоритизации.
- RC-06 (story-arc → audio) оказался невалидным механизмом: → защита: §3 file:line на RC.
- Negative claims Codex (music_role, script_quality_report «мертвы») опровергнуты `rg`:
  → защита: §3 запрет negative claim без локального поиска.
- N=3 ролика: «3/3» — слабая статистика: → защита: в отчёте указывать N, не обобщать.

## Когнитивные искажения агента в этой области

### Severity inflation
**Симптом:** роли ставят P0 половине находок; 18 «первопричин» на 3 ролика.
**Защита:** §4.1 личная перепроверка всех P0/P1 + §3 дедуп до приоритизации.

### Metric literalism
**Симптом:** «coverage 75% < 85% → чинить каптионы» без вопроса, что метрика меряет.
**Защита:** §4.2 — читать расчёт метрики И рендер-consumer перед вердиктом.

### Новый код по умолчанию
**Симптом:** план фикса = «написать постпроцесс», хотя repair-модуль уже есть в репо.
**Защита:** §4.4 rg существующих механизмов перед проектированием нового.

### Ещё-один-проход bias
**Симптом:** «давай перезапустим отсмотр, может ещё что найдём» при неприземлённом фиксе.
**Защита:** Принятое решение — повтор только после ре-рендера/нового контента.

## Связанные скиллы

- `/delegate` — бриф Codex-верификатора (§5)
- `/triage` — если после §4 осталось ≥3 конкурирующих корня одного симптома
- `/check` — верификация фикса против acceptance из §4.3
- `/known-symptom-fixes` §3-4 (бывш. `rules/antigravity-cdp.md`, `rules/antigravity-worktreeconfig.md`) — механика запуска AGY

## FORBIDDEN

- Принимать RC без file:line как подтверждённый
- Начинать фикс до арбитража §4 (по сырому списку RC)
- Negative claim без локального `rg`
- Повторный отсмотр тех же артефактов без ре-рендера
- Отчёты только в brain-директории AGY

## Hard fail

- Нет каталога симптомов с таймкодами → стадия 1 не выполнена, RCA не запускать
- Bottleneck без offline acceptance-команды → план не верифицируем
- Вердикты по корням без Read текущего checkout → арбитраж недействителен
