# 📊 Research Data Standard (anti-hallucination)

**Класс:** micro

Цель: не “думать по памяти”, а опираться на данные и оставлять проверяемый след.

> **Теги источника [O/I/S/A].** Помечай ключевые факты тегом происхождения: **[O]** Observed
> (наблюдение/лог/замер), **[I]** Inferred (вывод/расчёт), **[S]** Stated (со слов/документ),
> **[A]** Assumed (допущение). Канон тегов — `_agent_shared/rules/core-anti-bias.mdc`.

## 1) Вход (инвентаризация)
- Явно перечисли входные файлы/таблицы и их пути.
- Для файлов: размер, формат, кодировка (если применимо).
- Если входов нет — остановись и запроси недостающее.

## 2) Схема (обязательный минимум)
Для каждого ключевого источника:
- `columns + types`
- `shape`
- `head(5)` (или эквивалент)
- `nunique()` / распределение для категориальных (если N небольшой)
- пропуски / дубликаты (если релевантно)

## 3) Примеры значений (чтобы не выдумывать смысл поля)
Для 5–10 критичных колонок:
- дай 5+ реальных примеров значений
- пометь подозрительные паттерны (локали дат/валют, смешанные типы, “0/1”, строки-числа)

## 4) Гипотеза и критерий успеха (на каждый шаг)
- 1–2 предложения: что именно проверяем/доказываем.
- Критерий успеха: что должно получиться (число/таблица/проверка/инвариант).
- Если данных недостаточно — пометь как допущение.

## 5) Мини-эксперимент (data-first)
- Сначала самый узкий запрос/скрипт, который подтверждает/опровергает гипотезу.
- Никаких “больших” прогонов, пока не подтверждена схема и смыслы полей.

## 6) Output (как сдавать результат)
- Список проверенных фактов (с путями к файлам и командами/шагами).
- Список допущений (пометь как **[A]**).
- Что нужно сделать, чтобы допущения стали **[O]** (наблюдением).

## 7) Нельзя
- Делать выводы о смысле полей без примеров значений.
- Подставлять “типичные” формулы, не сверив определения метрик в данных.
- Писать “всё ок” без минимального доказательства (схема + примеры + проверка).

## 8) Внешние источники (anti-hallucination при ресёрче рынка/конкурентов)

Когда данные не в локальных файлах, а во внешнем мире — LLM по умолчанию отвечает «по памяти»
(training data), а не свежими фактами. Дисциплина сбора:

- **Не выдумывай — ищи.** Любой рыночный факт → web-поиск / AI-deep-search с цитатами /
  браузерная автоматизация для JS-сайтов. Платформенные тулы здесь намеренно не названы —
  используй доступный в твоём рантайме.
- **Цитируй конкретный URL.** Запрещено «по данным исследований» без ссылки. Каждый факт —
  с источником, помеченным **[S]** (со слов источника), а не **[O]**.
- **Приоритет источников** (от надёжного к слабому): первичные данные (GitHub Issues,
  StackOverflow, реальные тикеты) → агрегаторы отзывов (TrustPilot/G2/Capterra) → форумы
  (Reddit, bias) → новости (контекст, возможен PR) → блоги компаний (наименее надёжно).
- **Валидация перед использованием:** источник датирован (не старше ~2 лет)? авторитетен
  (не анонимный блог)? факт подтверждён 2+ источниками? URL реально существует (не галлюцинация)?
- **API-first** там, где есть официальный API (стабильнее парсинга). **User-assisted fallback:**
  если методы не сработали — собери список URL и попроси владельца открыть/скопировать контент.
