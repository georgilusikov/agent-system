# RAT Framework: Risky Assumption Test (Product Launch)

**Методология:** Advanced JTBD (AJTBD)
**Назначение:** Выявление и приоритизация Top‑5 рискованных предположений при запуске продукта.
**Связано:** [04_launch_pmf](../../config/resources/jtbd-3/theory/04_launch_pmf.md), [ALL-PROMPTS RAT](../prompts/ALL-PROMPTS.md#1-rat--оценка-рискованных-предположений), [product-workflows](../workflows/product-workflows.md).

---

## 1. Суть и цели

- **RAT** — структурная проверка ключевых предположений, от которых зависит успех продукта. Каждое формулируется как проверяемое утверждение.
- **Главная цель на старте** — не «запустить продукт», а быстро проверить жизнеспособность идеи и при необходимости «убить» слабую гипотезу до больших затрат.
- **Результат RAT** — ровно **Top‑5 рисков** с Score = P×I, методами проверки и без лишнего описания процесса.

---

## 2. Блок-ввод (7 полей)

| # | Поле | Описание |
| --- | --- | --- |
| 1 | **Продукт и стадия** | Название, стадия (idea / MVP / ранние продажи / рост) |
| 2 | **Сайт / ссылка** | URL продукта или лендинга (если есть) |
| 3 | **Гипотезы сегмента (Core / Big Jobs)** | Core Jobs, Big Jobs, описание людей/компаний сегмента |
| 4 | **Стадия продукта** | Текущая стадия (уточняет п.1 при необходимости) |
| 5 | **Платящие клиенты** | Количество платящих клиентов (если есть) |
| 6 | **Монетизация** | Бизнес-модель, тарифы, цены |
| 7 | **Главная бизнес-задача** | Ключевая задача на текущий момент |

**Gate достаточности:** вход считается достаточным, если заполнено **≥5 из 7** пунктов.

- Если **gate пройден** → не задавать уточняющих вопросов, сразу выводить Top‑5.
- Если **не пройден** → спросить **только** недостающие пункты из списка.
- Если каких‑то цифр нет → использовать **«допущения»** и всё равно формировать Top‑5.

---

## 3. Категории риска (канон)

| Категория | Смысл |
| --- | --- |
| **Рынок** | Спрос на рынке, размер, динамика |
| **Сегмент** | Экономически привлекательный сегмент (размер, платёжеспособность) |
| **Ценность / готовность купить** | Ценностная гипотеза, Jobs, готовность платить |
| **Юнит-экономика** | Маржинальность, когорты, LTV/CAC |
| **Привлечение и масштабирование спроса** | Каналы, CAC→LTV, масштабируемость |
| **Операционные / регуляторные / технологические** | Остальные риски |

Каждому риску назначается **ровно одна** категория.

---

## 4. Алгоритм

1. **Сопоставить вход с блоком-вводом** → применить gate.
2. **Собрать RAT-предположения** из описания (при отсутствии данных — пометить «допущение»).
3. **Disinformation Check:** помечать **высоким риском (P=5)** предположения, основанные на хайпе/трендах без данных (например, «AI сейчас везде»).
4. **Первичная приоритизация:** выделить гипотезы, чья неверность **«убьёт» продукт**.
5. **Классифицировать** по категориям риска (см. канон).
6. **Конкретизировать** каждую гипотезу: проверяемая формула с цифрами/условиями; при отсутствии цифр — диапазоны/оценки с пометкой «допущение».
7. **Спроектировать 2–5 быстрых и дешёвых тестов:**
   - решенческие интервью,
   - лендинги с тестовым трафиком,
   - прототип / UX-тесты,
   - A/B-тесты и т.п.
8. **Score = P×I.** Сортировка: **Score↓**; при равенстве — **I↓**, затем **P↓**.
9. **Итог:** ровно **5 карточек** рисков, **без** описания процесса.

---

## 5. Шкалы P и I

### Вероятность (P 1–5)

| P | Уровень | Критерии |
| --- | --- | --- |
| 1 | Низкая | Есть твёрдая эмпирика: продажи, эксперименты, кейсы |
| 2 | — | Косвенные сигналы + частичная эмпирика |
| 3 | Средняя | Аналогии на соседних рынках |
| 4 | — | Только слабые индикаторы |
| 5 | Высокая | Чистая гипотеза, хайп/тренды без данных |

**Источник знания** (по возможности помечать в карточке):

- **[O]** Observation — наблюдение, данные.
- **[I]** Inference — логический вывод.
- **[S]** Say — слова (эксперты, опросы).
- **[A]** Assumption — допущение.

### Последствия (I 1–5)

| I | Уровень | Смысл |
| --- | --- | --- |
| 1 | Локальный сбой | Без влияния на выживаемость |
| 3 | Серьёзный откат | Откат ключевых метрик, заморозка роста |
| 5 | Критично | «Убьёт» бизнес, разрыв юнит-экономики, критический рег-риск |

**Денежная оценка I** (если прямых цифр нет): оценить через один из ориентиров — % выручки месяца, «месяцы burn», доля валовой маржи на когорту, доля LTV выбранного сегмента.

## 6. Шаблон карточки риска

Для каждого из Top‑5:

1. **Название:** краткое, ёмкое имя риска.
2. **Предположение:** конкретная проверяемая формула с цифрами/условиями. При необходимости: **Источник знания** [O] / [I] / [S] / [A].
3. **Риск:** последствия для бизнеса — почему это критично.
4. **Категория риска:** одна из шести (см. канон).
5. **Вероятность (P 1–5):** с кратким обоснованием.
6. **Последствия (I 1–5):** обоснование, при возможности — денежная оценка.
7. **Методы проверки:** 2–5 быстрых и дешёвых экспериментов (интервью, лендинг+трафик, прототип/UX, A/B и т.д.).
8. **Score = P×I** и **место в рейтинге**.

---

## 7. Обязательные правила

- **Первый ответ:** либо запрос **только** недостающего из блока-ввода, либо (если gate пройден) **сразу** Top‑5. Никаких лишних вопросов.
- **Критичность = Score = P×I.** При возможности указывать денежную оценку I.
- **Мало данных** → выдавать временный Top‑5 с пометкой «допущения».
- **Запрет:** не использовать слова «боль», «страх» — только **Jobs, критерии, мотивации**.

---

## 8. Связь с PMF и JTBD

- Пять типичных RAT-предположений (см. [04_launch_pmf](../../config/resources/jtbd-3/theory/04_launch_pmf.md)): **рынок → сегмент → ценность → юнит-экономика → каналы.** Плюс операционные/уникальные риски продукта.
- Приоритизация: сначала гипотезы с **высокой вероятностью ошибки**, **катастрофическими последствиями** и **низкой стоимостью проверки**. Часто первым идёт **сегмент**.
- RAT встроен в workflow «Запуск продукта»: RAT → сегментация → граф работ → рекрут → лендинг/MVP.

## 10. Краткий чек-лист

- [ ] Собраны ≥5 полей из блока-ввода.
- [ ] Gate пройден → сразу Top‑5; иначе — запрошено только недостающее.
- [ ] Disinformation Check выполнен (хайп/тренды без данных → P=5).
- [ ] У каждого риска: категория, P, I, Score, методы проверки.
- [ ] Сортировка: Score↓, при равенстве I↓, затем P↓.
- [ ] Нет «боли»/«страха» — только Jobs, критерии, мотивации.
