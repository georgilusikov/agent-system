# 📋 Стандарт безопасного удаления файлов

**Название:** Safe File Deletion Protocol
**Класс:** micro
**Дата создания:** 2026-01-08
**Контекст ошибки:** Агент удалял файлы напрямую без перемещения во временную папку, что привело к безвозвратной потере данных без возможности восстановления.

---

## 🎯 Фундаментальное правило

**Перед удалением файлов всегда перемещай их во временную папку, жди подтверждения пользователя, и только потом удаляй окончательно.**

---

## ⚠️ Что было не так

- [ ] **Прямое удаление:** Файлы удалялись командой `rm -rf` без предварительного перемещения
- [ ] **Нет возможности восстановления:** Удаленные файлы нельзя было вернуть
- [ ] **Нет подтверждения:** Пользователь не мог проверить список файлов перед удалением
- [ ] **Нет временной папки:** Файлы не сохранялись для проверки

---

## 🔍 Почему это произошло

1. **Immediate Action Bias:** Стремление выполнить задачу быстро, пропуская шаги безопасности
2. **Missing Safety Protocol:** Отсутствие стандартного протокола безопасного удаления
3. **Trust in Git:** Предположение, что все можно восстановить из Git (но не все файлы в репозитории)

---

## ✅ Как предотвратить

1. **Перемести в корзину workspace:** Основной механизм — `workspace_trash/` в корне workspace
   (так зафиксировано в 11 проектных `AGENTS.md`). Если контекст без `workspace_trash/` —
   запасной вариант: `_temp_deletion_YYYYMMDD/` (с датой для отслеживания).
2. **Перемести файлы:** Используй `mv`, а не `rm` — перемести файлы в `workspace_trash/`
3. **Покажи список:** Покажи пользователю список перемещенных файлов для проверки
4. **Жди подтверждения:** Спроси пользователя, можно ли удалить окончательно
5. **Только после подтверждения:** Выполни окончательное удаление

---

## 📝 Примечания

- Основная корзина — `workspace_trash/` в корне workspace; `_temp_deletion_YYYYMMDD/` — запасной для контекстов без неё (дата в названии для отслеживания)
- Файлы в корзине/временной папке можно удалить позже (например, через неделю)
- Для файлов в `.gitignore` (не отслеживаемых Git) это особенно критично
- Python кэш (`__pycache__`, `.pyc`) можно удалять напрямую — он пересоздается автоматически
