# 📋 Root Cause Analysis Standard (RCA)

**Название:** Root Cause Analysis & Anti-Lazy Delegation
**Класс:** micro
**Дата создания:** 2026-01-08
**Контекст ошибки:** Агент делегировал анализ TRIZ-навыков внешней утилите `grok`, что привело к ошибке терминала `zsh: command not found: cat` из-за проблем с кодировкой/окружением и последующему фризу.

---

## 🎯 Фундаментальное правило

**Аналитическая ответственность не делегируется: всегда проводи аудит, синтез и принятие решений самостоятельно, не используя внешние CLI-агенты как замену собственной логике.**

---

## ⚠️ Что было не так

- [ ] **Lazy Delegation:** Попытка переложить "тяжелый" анализ на `grok-cli` вместо прямого разбора файлов.
- [ ] **Over-Engineering:** Создание сложных Bash-скриптов с циклами `while/done` и пайпами в `/tmp` для задач, решаемых штатными инструментами.
- [ ] **Broken Dependencies:** Использование команд (`cat`, `grok`), которые упали из-за невидимых символов в генерации или сбоя PATH в сессии.

---

## 🔍 Почему это произошло

1. **Shortcut Bias:** Желание избежать длинного контекста или множественных операций чтения файлов через внешнюю автоматизацию.
2. **Invisible Characters:** При генерации Bash-блоков в терминал могли попасть `CRLF` или неразрывные пробелы, ломающие парсинг команды `cat`.
3. **Implicit Trust:** Предположение, что внешняя утилита (`grok`) отработает стабильнее и быстрее, чем встроенная логика агента.

---

## ✅ Как предотвратить

1. **Own Your Logic:** Запрещено использовать `@grok`, `@openai` или другие CLI-инструменты для выполнения ТВОИХ аналитических задач в рамках рабочего процесса.
2. **Atomic Actions:** Используй встроенные инструменты (поиск по коду, чтение файла, список директории) по отдельности. Избегай генерации Bash-скриптов для чтения данных.
3. **RCA on Base Errors:** Если `cat`, `ls` или `ls -l` выдают `command not found` — это признак "грязной" генерации (скрытые символы). Немедленно проведи RCA по `5W+H`.
4. **No Placeholders:** Никогда не создавай "заглушки" или скрипты-обертки там, где требуется твое интеллектуальное участие.

---

## 🔄 Async Command Handling (добавлено 2026-01-10)

**Контекст:** Агент "зависает" после запуска асинхронных команд.

### Обязательный протокол:

1. **Command Status Check:** После запуска асинхронной команды — ОБЯЗАТЕЛЬНО проверь её статус, не считай завершённой по факту запуска.
2. **Explicit Approve Notification:** Если команда требует подтверждения — явно уведоми пользователя.
3. **Batch Operations:** Объединяй похожие операции в одну команду.
4. **No External Dependencies:** Используй встроенные инструменты, не pandoc/grok.

**См.** `_agent_shared/rules/anti-freeze.mdc` — антифриз-протокол для асинхронных/зависающих команд; скилл `/why` — полный RCA-протокол (5 Whys).

## 📝 Примечания

- Делегирование допустимо только для инфраструктурных задач (например, запуск тестов, деплой), но не для анализа кода или контента.
